The LIKE Operator

15 Min Read • Module 1: Basics

The Directory Search & Position Matching Analogy

Imagine searching an enterprise directory of employees for the name Mrinal:

1. Starts with 'M': Searching with 'M%' matches the letter M followed by any sequence of characters.

2. Ends with 'l': Searching with '%l' matches any sequence of characters concluding strictly with the letter l.

3. Fixed 2nd & 3rd Characters ('ri'): Searching with '_ri%' uses the underscore _ to match exactly one arbitrary character at position 1, followed strictly by ri at positions 2 and 3.

4. Precision Combination: Combining all three rules (starts with M, 2nd & 3rd are ri, and ends with l) produces 'Mri%l', pinpointing Mrinal with surgical accuracy.

The SQL LIKE operator pairs the multi-character % wildcard and single-character _ placeholder for flexible textual pattern matching.

1. Canonical LIKE Operator Syntax

The LIKE operator tests whether a string column matches a specified wildcard pattern expression:

Grammar Blueprint: Wildcard Pattern Matching with LIKE 
-- Standard Declarative LIKE Syntax Blueprint
SELECT column1, column2, ...
FROM table_name
WHERE column_name LIKE 'pattern';

-- Negated Pattern Blueprint
SELECT column1, column2, ...
FROM table_name
WHERE column_name NOT LIKE 'pattern';

LIKE Blueprint Breakdown

How the database engine processes text patterns:

  • The Percent Sign (%): Matches zero, one, or any number of arbitrary characters. Useful for prefixes, suffixes, and contains searches.
  • The Underscore (_): Matches strictly one single character at an exact positional slot. Two underscores '__' match exactly two characters.
  • Safe Pattern Enclosure: Patterns must always be enclosed in single quotes ' '. SQL string literals containing double quotes or backslashes require standard string escaping.

2. Prefix Matching: Searching Personnel by Initial Letter

Retrieve employee records whose first name begins with the letter M on the active employees corporate directory:

Query: Finding Staff with First Names Starting with 'M' 
-- Find employees whose first name starts with 'M'
SELECT employee_id, first_name, last_name, department, salary
FROM employees
WHERE first_name LIKE 'M%'
ORDER BY first_name ASC;

Prefix Pattern Breakdown

How the prefix filter surfaces qualifying personnel:

  • Exact Lead Character: 'M%' requires the first character to strictly be M.
  • Matching Roster: Instantly returns Michael Chang (Operations, $105,000) and Mrinal Prashar (Executive, $150,000).
  • High Performance (SARGable): Because the prefix is constant, production database engines can execute high-speed B-Tree index seeks rather than scanning every record.

3. Positional Offset Matching: The Single-Character Underscore (_)

Match names having any arbitrary lead character followed strictly by the sequence ri at characters 2 and 3:

Query: Exact Second-and-Third Character Sequence 
-- Matches any 1 character at slot 1, followed by 'ri', followed by any text
SELECT employee_id, first_name, last_name, department
FROM employees
WHERE first_name LIKE '_ri%'
ORDER BY first_name ASC;

Positional Underscore Breakdown

How the positional underscore isolates specific character slots:

  • Slot 1 (_): Matches any single arbitrary character (e.g., M or B).
  • Slots 2 & 3 (ri): Strictly locks the 2nd and 3rd letters to the characters r and i.
  • Remaining Slots (%): Allows the name to continue with any trailing characters.
  • Resulting Rows: Accurately matches Mrinal (M + ri + nal) and Brian (B + ri + an).

4. Substring Search: Finding Transactions Containing Specific Keywords

Locate all ledger entries containing the keyword Deposit anywhere in the description on transactions:

Query: Substring Search for 'Deposit' Ledger Entries 
-- Retrieve transactions with 'Deposit' anywhere in the description
SELECT transaction_id, account_id, transaction_type, amount, description, status
FROM transactions
WHERE description LIKE '%Deposit%'
ORDER BY amount DESC;

Substring Contains Breakdown

How the enclosing percent signs capture internal keywords:

  • Flanking Wildcards: Wrapping a token in '%...%' matches the search term regardless of whether it appears at the beginning, middle, or end of the string.
  • Identified Transactions: Captures both Monthly Salary Direct Deposit and other deposit credits.
  • Case Sensitivity Note: AlaSQL and SQL Server evaluate string comparisons case-insensitively by default, whereas PostgreSQL requires ILIKE.

5. Suffix Matching: Finding Patronymic Family Names

Query the customers directory for customers whose last names end with the traditional patronymic suffix son (such as Jackson, Johnson, or Anderson):

Query: Suffix Search for Surnames Ending in 'son' 
-- Find customers whose surname ends with 'son'
SELECT customer_id, first_name, last_name, city, credit_score
FROM customers
WHERE last_name LIKE '%son'
ORDER BY customer_id ASC
LIMIT 10;

Suffix Matching Breakdown

How the terminal suffix filter extracts targeted customer clusters:

  • Terminal Character Requirement: '%son' accepts any preceding letters, but mandates that the final three characters must strictly be s, o, and n.
  • Targeted Population: Successfully retrieves customer profiles like Johnson and related lineages.
  • LIMIT Clause: Caps the result set to the first 10 qualifying accounts for rapid auditing and responsive page rendering.

6. Negative Pattern Inversion: The NOT LIKE Operator

Combine operational filtering with pattern exclusions to filter out recurring routine fees and cash withdrawals:

Query: Excluding Routine Fees and ATM Withdrawals 
-- Filter completed transactions excluding Fee and ATM withdrawals
SELECT transaction_id, account_id, transaction_type, amount, description
FROM transactions
WHERE status = 'Completed' 
  AND description NOT LIKE '%Fee%' 
  AND description NOT LIKE '%ATM%'
ORDER BY amount DESC;

NOT LIKE Inversion Breakdown

Filtering out routine maintenance noise from core commercial cash flow:

  • Pattern Inversion: NOT LIKE '%Fee%' rejects any ledger entry containing the word "Fee" in its description.
  • High-Value Flow Isolation: Preserves primary transactions like commercial wire transfers, contract payments, and salary credits.

Core Concepts & Engine Mechanics

The LIKE operator evaluates strings against pattern definitions using ANSI SQL's wildcard tokens: % (arbitrary sequence) and _ (single positional slot).

Detailed Technical Breakdown & Performance Profile

Search Objective Pattern Syntax Wildcard Breakdown Matching Examples Index Seek (SARGable)?
1. Starts with 'M' LIKE 'M%' Slot 1 must be M. % matches any subsequent characters. Mrinal, Michael, Maria, Maya Yes (B-Tree Index Seek)
2. Ends with 'l' LIKE '%l' % accepts any prefix. The final character must be l. Mrinal, Daniel, Michael, Paul No (Full Table Scan)
3. Fixed 2nd & 3rd 'ri' LIKE '_ri%' _ (1 slot) + ri (slots 2 & 3) + % (arbitrary remainder). Mrinal, Brian, Eric No (Leading wildcard scan)
4. Precision Combo LIKE 'Mri%l' Starts with M, fixed ri at slots 2 & 3, and ends with l. Mrinal Yes (Fixed lead prefix)

Positional Offset & Length-Locking Rules

While % is greedy and consumes arbitrary lengths, the underscore _ enforces exact positional counting:

  • Single Slot ('_ri%'): Character 1 is arbitrary; characters 2 & 3 are strictly ri.
  • Double Slot Offset ('__ri%'): Characters 1 & 2 are arbitrary; characters 3 & 4 are strictly ri (e.g., Adrian).
  • Exact Length Locking ('Mri___'): Starts with Mri and contains exactly 6 characters in total (3 letters + 3 underscores), matching Mrinal but rejecting Mrinalini.

Chapter Summary

The LIKE operator provides foundational pattern searching across relational text columns, balancing powerful character-matching capabilities with index seek considerations.

  • Wildcard Primitives: Use % for multi-character flexibility and _ for exact character slot position checks.
  • SARGability Best Practice: Prefix patterns ('ABC%') utilize B-Tree index seeks; leading wildcards ('%ABC') force engine table scans.
  • Negation with NOT LIKE: Swiftly filter out noise or unwanted subcategories by combining standard boolean conjunctions with NOT LIKE.
