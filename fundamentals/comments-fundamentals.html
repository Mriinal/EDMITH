Code Comments & Documentation

7 Min Read • Beginner • Language Agnostic

1. What are Code Comments?

A code comment is a programmer-readable annotation inserted directly into the source code of a computer program. Comments are completely ignored by compilers and interpreters; they produce zero machine instructions and consume zero runtime memory.

Their sole purpose is to explain intentions, document architectures, and provide context for human software engineers—including teammates, code reviewers, and your future self.

2. The Cardinal Rule of Engineering Comments

Explaining Why vs. What

Good code tells the computer what to do and shows how it is done. Good comments explain why a specific decision, trade-off, or workaround was chosen.

3. Good Comments vs. Bad Comments

Bad (Redundant / Noise)

// Set count to zero
count = 0;

// Add 1 to age
age = age + 1;

Restates the obvious. Adds visual clutter without providing any insight.

Good (Contextual / Valuable)

// Adding a 50ms backoff delay to prevent
// overwhelming the payment gateway during peak sales
apply_delay(50);

Explains the business reason and underlying architectural necessity.

4. Universal Varieties of Comments

  • Single-Line Comments: Brief, inline notes clarifying non-obvious mathematical formulas or algorithm edge cases.
  • Block / Multi-Line Comments: High-level summaries at the top of a file or module outlining its architectural role and dependencies.
  • API / Docstring Comments: Standardized documentation blocks preceding functions that formally define parameter types, return values, and thrown exceptions.

5. Key Takeaways

  • Comments are human annotations stripped out during compilation/interpretation.
  • Never write comments that simply repeat what clean code already states clearly.
  • Use comments to document business rationale, constraints, and non-obvious decisions.
  • Keep comments synchronized with code changes; misleading comments are worse than no comments.
