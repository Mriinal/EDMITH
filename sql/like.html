The LIKE Operator

15 Min Read • Module 1: Basics

The Directory Search & Position Matching Analogy

Imagine searching an enterprise directory of 50,000 employees for the name Mrinal:

  • 1. Starts with 'M': You search with 'M%' (the letter M followed by any number of characters).
  • 2. Ends with 'L': You search with '%l' (any sequence of characters that concludes with the letter l).
  • 3. Fixed 2nd & 3rd Characters ('RI'): You search with '_ri%' (the underscore _ matches exactly one character at position 1, followed strictly by ri at positions 2 and 3).
  • 4. Precision Combination: Combining all three rules (starts with M, 2nd & 3rd are ri, and ends with l) gives 'Mri%l', pinpointing Mrinal instantly!

The LIKE operator combines the power of the % wildcard (multiple characters) and the _ wildcard (exact single position) for surgical pattern matching.

Syntax & Statement Grammar

The standard SQL syntax and pattern rules for The LIKE Operator:

SQL Syntax Grammar • like.sql 
-- 1. Search for names STARTING with 'M' (% matches any trailing characters)
SELECT * FROM employees
WHERE first_name LIKE 'M%';

-- 2. Search for names ENDING with 'l' or 'L' (% matches any leading characters)
SELECT * FROM employees
WHERE first_name LIKE '%l';

-- 3. Search for names where 'RI' is FIXED at character positions 2 and 3
-- (_ matches exactly 1 character at pos 1, followed by 'ri', followed by %)
SELECT * FROM employees
WHERE first_name LIKE '_ri%';

-- 4. Precision Combo: Starts with 'M', 2nd & 3rd are 'ri', and ends with 'l' ('Mrinal')
SELECT * FROM employees
WHERE first_name LIKE 'Mri%l';

Core Concepts & Engine Mechanics

The LIKE operator evaluates strings against pattern definitions using two fundamental ANSI SQL wildcard tokens: % (zero or more arbitrary characters) and _ (strictly one single character at an exact position).

  • The Percent (%) Wildcard: Represents zero, one, or multiple arbitrary characters.
  • The Underscore (_) Wildcard: Represents strictly one single character at an exact positional slot.
  • Index Friendliness (SARGability): Patterns with fixed prefixes (e.g. 'M%') can utilize B-Tree index seeks; patterns with leading wildcards (e.g. '%l' or '_ri%') force full table scans.
  • Case Sensitivity: Standard SQL LIKE is case-sensitive in PostgreSQL and case-insensitive in MySQL; use ILIKE or UPPER() for case-insensitive portability.

Detailed Technical Breakdown & Syntax Comparison

Search Objective Pattern Wildcard Breakdown Matching Examples Index Friendly?
1. Starts with 'M' LIKE 'M%' Position 1 must be M. % matches any remaining characters. Mrinal, Michael, Maria, Maya, Mark Yes (B-Tree Index Seek)
2. Ends with 'l' LIKE '%l' % accepts any prefix. The final character must strictly be l. Mrinal, Daniel, Michael, Paul, Gabriel No (Full Table Scan)
3. Fixed 2nd & 3rd 'RI' LIKE '_ri%' _ (1 arbitrary letter) + ri (fixed slots 2 & 3) + % (rest). Mrinal, Brian, Eric, Kristin, Aria No (Leading wildcard)
4. Precision Combo LIKE 'Mri%l' Starts with M, fixed ri at slots 2 & 3, and ends with l. Mrinal Yes (Starts with fixed prefix)

Why the Underscore (_) is Critical for Positional Searches

While the percent sign (%) is greedy and matches an arbitrary length of characters, the underscore (_) acts as a single-character placeholder. Each underscore accounts for precisely one byte / character position:

  • Positional Offset: '_ri%' → Character 1 is anything, Characters 2 and 3 are strictly ri, followed by any text. Matches: Mrinal, Brian, Eric.
  • Multiple Offset Underscores: '__ri%' → Characters 1 and 2 are anything, Characters 3 and 4 are strictly ri. Matches: Chris, Adrian.
  • Exact Length Locking: 'Mri___' → Starts with Mri and has exactly 6 characters in total (3 letters + 3 underscores). Matches: Mrinal (6 letters), but rejects longer names like Mrinalini (9 letters).

Real-World Practical Scenario

Employee Directory Lookup (Finding 'Mrinal' and Pattern Filtering): Execute queries against a production employee dataset to demonstrate all three wildcard search requirements.

Production Queries • Employee Directory Lookup (Finding 'Mrinal' and Pattern Filtering) 
/* ========================================================
   Sample Employee Roster:
   101 | Mrinal  | Sharma    | Data Platform   | mrinal@edmith.com
   102 | Michael | Vance     | Cloud DevOps    | michael@edmith.com
   103 | Daniel  | Craig     | QA Security     | daniel@edmith.com
   104 | Brian   | Kernighan | Systems Kernel  | brian@edmith.com
   105 | Maria   | Garcia    | Data Science    | maria@edmith.com
   106 | Eric    | Raymond   | Architecture    | eric@edmith.com
   ======================================================== */

-- Requirement 1: Search for all employees whose name starts with 'M'
SELECT employee_id, first_name, department, email
FROM company_employees
WHERE first_name LIKE 'M%';
-- Matches: Mrinal, Michael, Maria

-- Requirement 2: Search for all employees whose name ends with 'l'
SELECT employee_id, first_name, department, email
FROM company_employees
WHERE first_name LIKE '%l';
-- Matches: Mrinal, Michael, Daniel

-- Requirement 3: Search where 'ri' is the FIXED 2nd and 3rd alphabet
SELECT employee_id, first_name, department, email
FROM company_employees
WHERE first_name LIKE '_ri%';
-- Matches: Mrinal (M+ri), Brian (B+ri), Eric (E+ri)

-- Requirement 4: Combination Filter (Starts with 'M', fixed 'ri' at 2nd/3rd, ends with 'l')
SELECT employee_id, first_name, department, email
FROM company_employees
WHERE first_name LIKE 'Mri%l';
-- Matches strictly: 101 | Mrinal | Data Platform | mrinal@edmith.com

Chapter Summary

The LIKE pattern-matching operator searches text fields for flexible string patterns using wildcard expressions. By pairing the percent wildcard (%) for arbitrary sequences with the underscore wildcard (_) for strict positional indexing, engineers can search prefixes, suffixes, and fixed-character patterns like 'M%', '%l', and '_ri%'.

  • Starts With ('M%'): The character 'M' followed by % matches any string beginning with M (e.g. Mrinal, Michael) and efficiently uses B-Tree indexes.
  • Ends With ('%l'): A leading % followed by 'l' matches any string concluding with the letter l (e.g. Mrinal, Daniel).
  • Fixed Position ('_ri%'): The single underscore _ skips exactly 1 character, fixing 'ri' strictly at character slots 2 and 3 (e.g. Mrinal, Brian, Eric).
  • Targeted Combination ('Mri%l'): Combining fixed prefixes, positional characters, and suffixes isolates exact target records like Mrinal.
  • Leading Wildcard Warning: Patterns beginning with a wildcard (e.g. LIKE '%l' or LIKE '_ri%') cannot use standard B-Tree index prefixes and trigger full table scans.
