Complete SQL Functions Reference & Dictionary

Complete Exhaustive Dictionary • Formal Syntax, Execution Mechanics, Dialect Matrix & Banking Scenarios

Welcome to the Complete SQL Functions Reference & Dictionary. Functions in SQL allow you to manipulate text strings, perform complex mathematical and statistical operations, compute temporal date math, calculate cumulative window partitions, sanitize NULL values, convert data types, and query modern JSON payloads. Every function below includes formal ANSI syntax, cross-database dialect variations (PostgreSQL, MySQL, SQL Server, Oracle, SQLite, and AlaSQL), technical mechanics & NULL behavior, and concrete production queries against EDMITH's 15-table banking database with interactive Try in Editor execution.

CONCAT()
String SQL Function

1. Formal Syntax

CONCAT(string1, string2, ... [, stringN])

Dialect Matrix: ANSI SQL standard. Supported across MySQL, PostgreSQL, Oracle, SQLite (via || or CONCAT in recent versions), and AlaSQL. Note: In SQL Server, CONCAT converts NULLs to empty strings, whereas in standard SQL / PostgreSQL, string1 || string2 returns NULL if any operand is NULL unless CONCAT() function is used.

2. How to Use It

Combines two or more text literals, column values, or converted expressions into a single continuous string. Returns VARCHAR/TEXT. Ignores NULL values in most modern engines (treating them as empty strings ''), preventing the entire concatenated result from collapsing into NULL.

3. Common Real-World Banking & Enterprise Use Cases

  • Generating full display names by combining first_name and last_name.
  • Constructing standardized transaction reference codes and invoice IDs.
  • Formatting physical branch mailing addresses into a single customer statement header.
  • Synthesizing unique surrogate keys for composite dimension warehousing.

4. Practical Scenarios & Examples

Scenario A: Generating Full Customer Profiles and Contact Handles

Concatenate customer identity fields into full formal titles and customer card summary labels.

SELECT 
    customer_id,
    CONCAT(first_name, ' ', last_name) AS full_name,
    CONCAT(city, ' Client (KYC: ', kyc_status, ')') AS client_badge,
    credit_score
FROM customers
ORDER BY credit_score DESC
LIMIT 10;
CONCAT_WS()
String SQL Function

1. Formal Syntax

CONCAT_WS(separator, string1, string2, ... [, stringN])

Dialect Matrix: Supported natively in MySQL, PostgreSQL, MariaDB, and SQL Server. In Oracle, use custom expressions or string concatenation with NVL. Supported in AlaSQL via user function or polyfill.

2. How to Use It

CONCAT_WS stands for 'Concatenate With Separator'. The first argument serves as the delimiter placed between all subsequent arguments. Automatically skips NULL arguments without appending orphaned separators, making it ideal for nullable address and location segments.

3. Common Real-World Banking & Enterprise Use Cases

  • Formatting multi-part branch physical addresses (address, city, state, postal_code).
  • Building comma-separated export lines for regulatory audit files.
  • Creating compound account identification strings with hyphen delimiters.
  • Assembling breadcrumbs or category hierarchies for banking portal navigation.

4. Practical Scenarios & Examples

Scenario A: Assembling Complete Branch Location Descriptors

Combine branch code, city, state, and postal code using a comma separator while gracefully skipping missing parts.

SELECT 
    branch_id,
    branch_name,
    CONCAT_WS(', ', branch_code, city, state, postal_code) AS formatted_address,
    is_active
FROM branches
ORDER BY branch_id ASC;
SUBSTRING() / SUBSTR()
String SQL Function

1. Formal Syntax

SUBSTRING(string FROM start [FOR length])
-- Alternate Dialects:
SUBSTR(string, start, length)

Dialect Matrix: SUBSTRING() is ANSI standard (PostgreSQL, SQL Server, MySQL). SUBSTR() is common in Oracle, SQLite, and MySQL. Note that SQL indexing is 1-based (first character is index 1, not 0).

2. How to Use It

Extracts a substring of a specified length starting at a 1-based character position. If length is omitted in supporting engines, it extracts through the end of the string. Negative start indices are supported in Oracle and SQLite to count backwards from the string end.

3. Common Real-World Banking & Enterprise Use Cases

  • Extracting branch routing prefixes from account numbers.
  • Masking sensitive credit card numbers or national tax identification numbers.
  • Extracting specific date tokens (e.g. YYYY) from unparsed ISO text timestamps.
  • Parsing batch file tracking numbers to isolate department codes.

4. Practical Scenarios & Examples

Scenario A: Extracting Account Prefix & Redacting Numbers

Isolate the first 3 characters of account numbers and combine with asterisks to safely display account previews.

SELECT 
    account_id,
    account_number,
    SUBSTRING(account_number, 1, 3) AS account_prefix,
    CONCAT(SUBSTRING(account_number, 1, 4), '****', SUBSTRING(account_number, 9, 2)) AS masked_display,
    account_type,
    balance
FROM accounts
ORDER BY balance DESC
LIMIT 10;
UPPER() / UCASE()
String SQL Function

1. Formal Syntax

UPPER(string)

Dialect Matrix: ANSI SQL standard. Universally supported in PostgreSQL, MySQL, SQL Server, Oracle, SQLite, and AlaSQL. UCASE() is a MySQL/ODBC alias.

2. How to Use It

Converts all alphabetic characters in the string expression to uppercase according to the database collation and character set. Non-alphabetic characters (numbers, punctuation, symbols) remain completely unaffected.

3. Common Real-World Banking & Enterprise Use Cases

  • Case-insensitive search matching and predicate comparison (UPPER(city) = 'NEW YORK').
  • Normalizing customer surname fields before running identity fraud checks.
  • Standardizing currency codes, account status tags, and SWIFT/BIC identifiers.
  • Generating capitalized official statements and formal legal correspondence.

4. Practical Scenarios & Examples

Scenario A: Standardizing Customer Cities & KYC Status for Audits

Convert city names and verification tiers to uppercase to produce uniform compliance reports.

SELECT 
    customer_id,
    first_name,
    UPPER(last_name) AS legal_surname,
    UPPER(city) AS normalized_city,
    UPPER(kyc_status) AS audit_kyc
FROM customers
WHERE UPPER(kyc_status) = 'VERIFIED'
ORDER BY last_name ASC
LIMIT 10;

Ensure all electronic mail addresses and login usernames are converted to canonical lowercase.

SELECT 
    customer_id,
    first_name,
    last_name,

LENGTH() / LEN()
String SQL Function

1. Formal Syntax

LENGTH(string)
-- SQL Server:
LEN(string)

Dialect Matrix: LENGTH() is ANSI standard (PostgreSQL, Oracle, SQLite, AlaSQL). SQL Server uses LEN(). In MySQL/PostgreSQL, CHAR_LENGTH() returns character count while LENGTH() returns octet byte length for multi-byte encodings.

2. How to Use It

Calculates and returns the integer number of characters in a string expression. In SQL Server LEN() excludes trailing spaces, whereas PostgreSQL and Oracle LENGTH() includes trailing whitespace.

3. Common Real-World Banking & Enterprise Use Cases

  • Validating card number or bank account number length compliance (e.g. exactly 10 or 16 digits).
  • Auditing customer phone numbers to identify missing country codes.
  • Detecting truncation risks when migrating character fields between staging and production tables.
  • Filtering out abnormal transaction descriptions that exceed standard layout limits.

4. Practical Scenarios & Examples

Scenario A: Validating Phone Number & Account Number Length Integrity

Measure character lengths across accounts and customer phone records to detect formatting anomalies.

SELECT 
    account_id,
    account_number,
    LENGTH(account_number) AS acc_num_length,
    account_type,
    status
FROM accounts
WHERE LENGTH(account_number) != 10
UNION ALL
SELECT 
    account_id,
    account_number,
    LENGTH(account_number) AS acc_num_length,
    account_type,
    status
FROM accounts
LIMIT 10;
TRIM() / LTRIM() / RTRIM()
String SQL Function

1. Formal Syntax

TRIM([LEADING | TRAILING | BOTH] [remstr FROM] string)
-- Shorthand variants:
LTRIM(string) -- Strips leading (left)
RTRIM(string) -- Strips trailing (right)

Dialect Matrix: ANSI SQL standard. Supported in PostgreSQL, Oracle, MySQL, SQL Server, and SQLite. AlaSQL supports standard TRIM(), LTRIM(), and RTRIM().

2. How to Use It

Removes whitespace (spaces, tabs, newlines) or a specified set of characters from the beginning, end, or both sides of a target string. If remstr is not specified, spaces are stripped by default.

3. Common Real-World Banking & Enterprise Use Cases

  • Cleaning legacy fixed-width mainframe flat files with trailing blank padding.
  • Sanitizing user form inputs before executing SQL INSERT or UPDATE statements.
  • Stripping leading zeros or unwanted prefix symbols from imported batch numbers.
  • Ensuring clean joins between foreign key strings that might carry hidden whitespace.

4. Practical Scenarios & Examples

Scenario A: Sanitizing Transaction Notes and Branch Codes

Remove accidental surrounding whitespace from branch codes and transaction descriptions.

SELECT 
    branch_id,
    branch_name,
    TRIM(branch_code) AS clean_branch_code,
    TRIM(city) AS clean_city
FROM branches
ORDER BY branch_id ASC
LIMIT 10;
REPLACE()
String SQL Function

1. Formal Syntax

REPLACE(string, search_substring, replacement_string)

Dialect Matrix: ANSI SQL standard. Supported universally in PostgreSQL, MySQL, SQL Server, Oracle, SQLite, and AlaSQL. Case-sensitivity matches the underlying collation.

2. How to Use It

Searches string for all occurrences of search_substring and replaces every occurrence with replacement_string. If replacement_string is empty (''), the matched substrings are completely deleted. Returns NULL if any argument is NULL.

3. Common Real-World Banking & Enterprise Use Cases

  • Scrubbing formatting symbols (hyphens, spaces, parentheses) from phone numbers.
  • Redacting confidential company keywords or legacy account identifiers in audit logs.
  • Standardizing street abbreviations (e.g. replacing 'St.' with 'Street', 'Ave' with 'Avenue').
  • Sanitizing dirty data during ETL migrations before loading into analytical data warehouses.

4. Practical Scenarios & Examples

Scenario A: Stripping Formatting Characters from Customer Phone Numbers

Remove country code prefixes, hyphens, and spaces to extract raw digits from phone numbers.

SELECT 
    customer_id,
    first_name,
    last_name,
    phone AS original_phone,
    REPLACE(REPLACE(phone, '-', ''), '+1-', '') AS clean_phone_digits
FROM customers
ORDER BY customer_id ASC
LIMIT 10;
POSITION() / INSTR() / CHARINDEX()
String SQL Function

1. Formal Syntax

POSITION(substring IN string)
-- MySQL / Oracle / SQLite:
INSTR(string, substring)
-- SQL Server:
CHARINDEX(substring, string)

Dialect Matrix: POSITION(... IN ...) is ANSI standard (PostgreSQL, MySQL). INSTR() is common in Oracle, SQLite, and MySQL. CHARINDEX() is SQL Server syntax.

2. How to Use It

Returns the 1-based integer position of the first occurrence of the target substring within the string. Returns 0 if the substring is not found (or NULL in Oracle if substring is NULL).

3. Common Real-World Banking & Enterprise Use Cases

  • Locating the '@' symbol in an email address to split username from domain.
  • Finding delimiter positions in compound ledger identifiers or log file entries.
  • Validating that a mandatory character sequence exists in transaction reference codes.
  • Dynamic string slicing when combined with SUBSTRING() to parse variable-length tokens.

4. Practical Scenarios & Examples

Scenario A: Isolating Email Domains by Locating the '@' Delimiter

Locate the exact character index of '@' in customer emails to extract corporate and personal domain providers.

SELECT 
    customer_id,
    email,
    POSITION('@' IN email) AS at_symbol_position,
    SUBSTRING(email, POSITION('@' IN email) + 1) AS email_domain
FROM customers
ORDER BY customer_id ASC
LIMIT 10;
LPAD() / RPAD()
String SQL Function

1. Formal Syntax

LPAD(string, target_length, pad_string)
RPAD(string, target_length, pad_string)

Dialect Matrix: Supported natively in PostgreSQL, Oracle, MySQL, and SQLite. In SQL Server, use RIGHT(REPLICATE('0', length) + string, length). Supported in AlaSQL.

2. How to Use It

Left-pads or right-pads the input string with repeated instances of pad_string until the total result reaches target_length characters. If the original string exceeds target_length, it is truncated.

3. Common Real-World Banking & Enterprise Use Cases

  • Zero-padding customer IDs or account numbers to standard 10-digit clearing house formats.
  • Aligning tabular financial exports for fixed-width text file transmissions.
  • Creating masked display strings (e.g. padding last 4 card digits with leading asterisks).
  • Constructing standardized hierarchical sort keys in chart-of-accounts trees.

4. Practical Scenarios & Examples

Scenario A: Formatting Standard 10-Digit Zero-Padded Customer Identifiers

Pad customer primary keys with leading zeros to generate banking account ledger serials.

SELECT 
    customer_id,
    LPAD(customer_id, 8, '0') AS zero_padded_id,
    CONCAT('CLI-', LPAD(customer_id, 6, '0')) AS formal_client_code,
    first_name,
    last_name
FROM customers
ORDER BY customer_id ASC
LIMIT 10;
LEFT() / RIGHT()
String SQL Function

1. Formal Syntax

LEFT(string, number_of_characters)
RIGHT(string, number_of_characters)

Dialect Matrix: Supported in SQL Server, MySQL, PostgreSQL, SQLite, and AlaSQL. In Oracle, use SUBSTR(string, 1, n) for LEFT and SUBSTR(string, -n) for RIGHT.

2. How to Use It

Extracts a given number of characters starting from the far left (beginning) or far right (end) of the string. Shorthand for equivalent SUBSTRING() operations.

3. Common Real-World Banking & Enterprise Use Cases

  • Extracting card last-4 digits for customer receipts and SMS alerts.
  • Retrieving country code prefixes from international IBAN numbers.
  • Isolating file extensions or file prefixes from audit attachment names.
  • Parsing zip code routing regions from alphanumeric postal codes.

4. Practical Scenarios & Examples

Scenario A: Extracting Branch Code Prefixes and Card Suffixes

Retrieve the first 2 characters of branch codes and card last digits for customer statements.

SELECT 
    card_id,
    account_id,
    card_type,
    network,
    card_number_last4,
    CONCAT('•••• •••• •••• ', card_number_last4) AS masked_card_display,

REVERSE()
String SQL Function

1. Formal Syntax

Dialect Matrix: Supported in SQL Server, MySQL, and PostgreSQL (via extension or user function). In Oracle, custom PL/SQL function or model clause is required.

2. How to Use It

Reverses the sequence of characters in a string, placing the last character first and the first character last.

3. Common Real-World Banking & Enterprise Use Cases

SELECT

INITCAP()
String SQL Function

1. Formal Syntax

INITCAP(string)

Dialect Matrix: Supported natively in Oracle and PostgreSQL. In SQL Server and MySQL, achieved via custom scalar functions or UPPER/LOWER combination. Supported in AlaSQL.

2. How to Use It

Converts the first letter of each word to uppercase and converts all remaining letters in each word to lowercase. Words are delimited by whitespace or non-alphanumeric characters.

3. Common Real-World Banking & Enterprise Use Cases

  • Formatting customer names entered in all-caps or all-lowercase on web signup forms.
  • Standardizing department names, merchant names, and street address titles.
  • Generating clean presentation reports and executive summary decks.
  • Customer statement header normalization.

Capitalize merchant company names and industry categories for presentation in mobile banking apps.

SELECT 
    merchant_id,
    merchant_name,
    UPPER(category) AS raw_category,
    CONCAT(UPPER(SUBSTRING(category, 1, 1)), LOWER(SUBSTRING(category, 2))) AS title_case_category,

FORMAT()
String SQL Function

1. Formal Syntax

FORMAT(number, decimal_places [, locale])
-- PostgreSQL / Oracle equivalent:
TO_CHAR(number, 'FM$999,999,990.00')

Dialect Matrix: FORMAT() is native in SQL Server and MySQL. PostgreSQL and Oracle use TO_CHAR() with format masks. AlaSQL supports standard JavaScript formatting.

2. How to Use It

Formats a number as a localized string with commas, grouping separators, and exact decimal place rounding.

3. Common Real-World Banking & Enterprise Use Cases

  • Displaying financial amounts with thousands separators ($1,250,500.00).
  • Formatting loan principal balances for customer billing notifications.
  • Formatting percentage ratios with fixed decimal precision (e.g. 5.75%).
  • Generating localized currency printouts for international branch locations.

4. Practical Scenarios & Examples

Scenario A: Formatting High-Value Account Balances with Thousand Separators

Round and format customer deposit balances into clean financial printout strings.

SELECT 
    account_id,
    account_number,
    account_type,
    balance,
    ROUND(balance, 2) AS rounded_balance,
    CONCAT('$', ROUND(balance, 2)) AS formatted_usd_balance
FROM accounts
WHERE balance >= 50000.00
ORDER BY balance DESC
LIMIT 10;
ROUND()
Numeric & Math SQL Function

1. Formal Syntax

ROUND(numeric_expression [, decimal_places])

Dialect Matrix: ANSI SQL standard. Universally supported in PostgreSQL, MySQL, SQL Server, Oracle, SQLite, and AlaSQL. If decimal_places is omitted, defaults to 0 (rounding to nearest whole integer).

2. How to Use It

Rounds a numerical value to the specified number of decimal positions using standard round-half-up or round-half-to-even mathematics (depending on engine float vs numeric types). Negative decimal_places rounds to powers of 10 (e.g. -2 rounds to hundreds).

3. Common Real-World Banking & Enterprise Use Cases

  • Calculating accrued interest on loans and deposit balances to exact cents.
  • Rounding tax liabilities and foreign exchange conversion calculations.
  • Presenting average credit scores and performance ratios in dashboard widgets.
  • Eliminating floating-point rounding artifacts in ledger balancing reconciliations.

4. Practical Scenarios & Examples

Scenario A: Calculating Accrued Monthly Loan Interest to Nearest Cent

Calculate monthly interest charges from loan principal and annual APR, rounded strictly to 2 decimal places.

SELECT 
    loan_id,
    loan_type,
    amount,
    interest_rate,
    ROUND(amount * (interest_rate / 100.0) / 12.0, 2) AS monthly_interest_charge,
    ROUND(amount, -3) AS amount_nearest_thousand
FROM loans
ORDER BY amount DESC
LIMIT 10;
FLOOR()
Numeric & Math SQL Function

1. Formal Syntax

FLOOR(numeric_expression)

Dialect Matrix: ANSI SQL standard. Supported universally across PostgreSQL, MySQL, SQL Server, Oracle, SQLite, and AlaSQL.

2. How to Use It

Returns the largest integer value that is less than or equal to the numeric expression. Always rounds downward toward negative infinity (e.g. FLOOR(4.9) = 4, FLOOR(-4.1) = -5).

3. Common Real-World Banking & Enterprise Use Cases

  • Determining completed elapsed years or completed loan tenure milestones.
  • Calculating integer loyalty reward points (e.g. 1 point per whole $10 spent).
  • Bucketing continuous numerical metrics into discrete histogram bins.
  • Calculating integer installment counts in amortized schedule models.

4. Practical Scenarios & Examples

Scenario A: Calculating Whole Customer Reward Points Earned

Award 1 reward point for every full $15 spent on merchant card transactions, rounding down fractions.

SELECT 
    payment_id,
    account_id,
    amount,
    FLOOR(amount / 15.0) AS reward_points_earned,
    payment_date,
    status
FROM merchant_payments
WHERE status = 'Completed'
ORDER BY amount DESC
LIMIT 10;
CEIL() / CEILING()
Numeric & Math SQL Function

1. Formal Syntax

CEIL(numeric_expression)
-- SQL Server / MySQL alias:
CEILING(numeric_expression)

Dialect Matrix: CEIL() is standard in Oracle, PostgreSQL, and SQLite. CEILING() is used in SQL Server. MySQL and AlaSQL support both CEIL() and CEILING().

2. How to Use It

Returns the smallest integer value that is greater than or equal to the numeric expression. Always rounds upward toward positive infinity (e.g. CEIL(4.1) = 5, CEIL(-4.9) = -4).

3. Common Real-World Banking & Enterprise Use Cases

  • Calculating total pagination pages needed (CEIL(total_rows / page_size)).
  • Determining minimum billable transaction blocks (e.g. rounding up billing minutes).
  • Calculating loan underwriting risk buffer allowances.
  • Allocating physical storage bins or branch cash shipment container counts.

4. Practical Scenarios & Examples

Scenario A: Calculating Full Statement Shipping Envelopes Required

Determine how many 50-sheet envelope packets are needed to mail customer statements, rounding up any remainder.

SELECT 
    customer_id,
    first_name,
    last_name,
    credit_score,
    CEIL(credit_score / 100.0) AS credit_tier_bracket
FROM customers
ORDER BY credit_score ASC
LIMIT 10;
ABS()
Numeric & Math SQL Function

1. Formal Syntax

ABS(numeric_expression)

Dialect Matrix: ANSI SQL standard. Universally supported across PostgreSQL, MySQL, SQL Server, Oracle, SQLite, and AlaSQL.

2. How to Use It

Calculates and returns the non-negative absolute magnitude of a numeric expression. Converts negative numbers into their positive counterparts while leaving positive numbers and zero unchanged.

3. Common Real-World Banking & Enterprise Use Cases

  • Reconciling ledger variance differences between debits and credits (|debits - credits|).
  • Computing audit discrepancy tolerances regardless of which direction the error occurred.
  • Calculating geometric or financial balance distance metrics.
  • Normalizing signed debit/credit transaction feeds into positive magnitude amounts.

4. Practical Scenarios & Examples

Scenario A: Reconciling Balance Differences Between Linked Accounts

Measure the absolute financial gap between checking accounts and high-yield savings portfolios.

SELECT 
    account_id,
    customer_id,
    account_type,
    balance,
    ABS(balance - 50000.00) AS deviation_from_target_reserve
FROM accounts
ORDER BY deviation_from_target_reserve ASC
LIMIT 10;
MOD() / %
Numeric & Math SQL Function

1. Formal Syntax

MOD(dividend, divisor)
-- Alternate syntax:
dividend % divisor

Dialect Matrix: MOD() is standard in Oracle, PostgreSQL, and MySQL. % is the operator in SQL Server and SQLite. AlaSQL supports both MOD() and %.

2. How to Use It

Divides the first number by the second number and returns the integer remainder. Essential for cyclic calculations, determining odd/even rows, and time-conversion math.

3. Common Real-World Banking & Enterprise Use Cases

  • Decomposing total loan tenure in months into remaining months after full years (term_months % 12).
  • Alternating zebra-striping rows or routing batch jobs across worker nodes (id % 4).
  • Scheduling recurring quarterly or bi-weekly compliance reviews.
  • Validating check-digit algorithms (e.g. Luhn Modulo 10 for credit cards).

4. Practical Scenarios & Examples

Scenario A: Decomposing Loan Terms into Full Years and Remaining Months

Separate loan tenure in months into complete years and odd remaining months using modulo arithmetic.

SELECT 
    loan_id,
    customer_id,
    loan_type,
    term_months,
    FLOOR(term_months / 12.0) AS term_full_years,
    MOD(term_months, 12) AS term_remainder_months
FROM loans
ORDER BY term_months DESC
LIMIT 10;
POWER() / POW()
Numeric & Math SQL Function

1. Formal Syntax

POWER(base, exponent)
-- MySQL alias:
POW(base, exponent)

Dialect Matrix: ANSI SQL standard. Universally supported in PostgreSQL, MySQL, SQL Server, Oracle, and AlaSQL.

2. How to Use It

Raises the numeric base to the power of exponent. Supports fractional and negative exponents for roots and inverse powers.

3. Common Real-World Banking & Enterprise Use Cases

  • Compound interest forecasting: Future Value = Principal * (1 + r)^n.
  • Statistical risk modeling and variance standard deviation calculations.
  • Exponential decay and asset depreciation algorithms.
  • Amortization formula evaluation for fixed-rate mortgages.

4. Practical Scenarios & Examples

Scenario A: Projecting 5-Year Compound Interest Growth on Term Accounts

Calculate compound maturity balance on high-balance accounts assuming a 5.5% annual yield over 5 years.

SELECT 
    account_id,
    account_number,
    account_type,
    balance AS initial_deposit,
    ROUND(balance * POWER(1.055, 5), 2) AS projected_5yr_compound_balance
FROM accounts
WHERE account_type IN ('Savings', 'Money Market')
ORDER BY balance DESC
LIMIT 10;
SQRT()
Numeric & Math SQL Function

1. Formal Syntax

SQRT(numeric_expression)

Dialect Matrix: ANSI SQL standard. Universally supported across PostgreSQL, MySQL, SQL Server, Oracle, SQLite, and AlaSQL. Attempting SQRT on negative numbers causes a domain error in strict engines or returns NaN/NULL.

2. How to Use It

Calculates and returns the non-negative square root of a non-negative numeric value. Returns FLOAT/DOUBLE precision.

3. Common Real-World Banking & Enterprise Use Cases

  • Calculating sample standard deviations and portfolio volatility (BETA).
  • Evaluating Euclidean distance formulas between geographic branch locations.
