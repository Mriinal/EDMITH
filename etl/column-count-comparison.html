Column Count Comparison

9 Min Read • Source-to-Target Validation

Structural Schema Completeness

Column count comparison validates that target tables contain the exact number of business, surrogate, and audit fields defined in the architectural DDL.

1. What is Column Count Comparison?

Column count comparison validates the structural breadth of database tables. It ensures that no required attributes were omitted from target DDL and that unexpected legacy columns were not accidentally deployed into production schemas.

2. Target Schema Column Taxonomy

  • Business Attributes: Core fields extracted directly from source systems (e.g., customer_name, order_date).
  • Surrogate Keys: System-generated synthetic primary keys (e.g., customer_sk, product_sk).
  • Slowly Changing Dimension (SCD) Attributes: Versioning metadata (e.g., effective_start_date, effective_end_date, is_current_flag).
  • Warehouse Audit Columns: Governance fields tracking lineage (e.g., etl_insert_timestamp, etl_job_id, etl_user_id).

3. Verification SQL Query

Information Schema Column Count Verification SQL 
-- Compare total column count against architectural specification
SELECT 
    table_name,
    COUNT(column_name) AS actual_column_count
FROM information_schema.columns
WHERE table_schema = 'edw' 
  AND table_name = 'dim_customer'
GROUP BY table_name;
-- Verify against STTM: Expected count (e.g., 24 columns)

Why This Matters in ETL Testing

ETL Testing Considerations

  • DDL vs STTM Alignment: Verify that target table column count matches the STTM exactly, including warehouse technical columns.
  • Dropped Field Risks: If column count is less than STTM specification, verify if downstream reporting dashboards rely on missing fields.
  • Column Order Validation: Beyond count, verify column ordinal position in file-based extracts (CSV/flat files) where order is critical.

Summary

Basics

Column count comparison confirms that target tables embody all required business, surrogate, SCD, and audit attributes specified in the architecture.

Key Points

  • Validates target table column volume against architectural specifications.
  • Ensures warehouse technical columns (SK, SCD flags, audit timestamps) are present.
  • Queries the database INFORMATION_SCHEMA to automate verification.
  • Guarantees that schema drift does not cause downstream dashboard failures.

Remember

Column count validation is fast and prevents deployment surprises. Run it as part of automated smoke test suites following database migrations.
