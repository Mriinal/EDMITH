SQL Wildcards Reference

15 Min Read • Module 3: References

The Card Game Wildcard Joker Analogy

Picture playing a card game with a standard deck containing fixed numbered cards and flexible Jokers:

1. Standard Exact Cards: A regular card like the 7 of Spades represents strictly that exact card and nothing else in a standard deal.

2. The Percent (%) Wildcard: The % symbol operates like a chameleon Joker that can represent zero, one, or dozens of characters of any kind.

3. The Underscore (_) Positional Wildcard: The _ symbol represents exactly one single character slot at that precise position.

4. Combining Patterns: Mixing fixed literal characters with wildcards creates versatile, high-precision search filters across large text columns.

SQL wildcards substitute for arbitrary characters in text searches, allowing developers to craft prefix, suffix, and positional matching queries.

Companion Tutorials: Review fundamental pattern-matching mechanics and negative filtering in The LIKE Operator and The NOT Operator.

Syntax & Statement Grammar

The standard SQL syntax and pattern rules for SQL Wildcards Reference:

SQL Syntax Grammar Blueprint 
-- 1. Universal ANSI SQL Wildcards (% and _)
SELECT * FROM table_name WHERE column_name LIKE 'prefix%';  -- Starts with prefix
SELECT * FROM table_name WHERE column_name LIKE '%suffix';  -- Ends with suffix
SELECT * FROM table_name WHERE column_name LIKE '%text%';    -- Contains text anywhere
SELECT * FROM table_name WHERE column_name LIKE '_at';      -- Exactly 3 letters ending in 'at'

-- 2. Character Sets and Ranges (SQL Server / T-SQL)
SELECT * FROM table_name WHERE column_name LIKE '[a-c]%';   -- Starts with a, b, or c
SELECT * FROM table_name WHERE column_name LIKE '[^a-c]%';  -- Does NOT start with a, b, or c

-- 3. Escaping Literal Wildcard Characters
SELECT * FROM table_name WHERE notes LIKE '%100!%%' ESCAPE '!'; -- Literal '100%'

SQL Wildcards Blueprint Breakdown

Core rules and architectural mechanics governing pattern matching and string filtration in relational engines:

  • Universal Symbols: % (matches zero or more characters) and _ (matches exactly one character) are supported across all ANSI SQL relational engines.
  • Leading Wildcard Performance Cost: Patterns starting with a wildcard (e.g. LIKE '%term') prevent B-tree indexes from performing range scans, forcing an expensive full table scan.
  • The ESCAPE Clause: To match literal % or _ symbols in text columns, designate an escape character (such as ! or \) using ESCAPE '!'.
  • Engine Variations: Square brackets [a-z] and [^a-z] are native to Microsoft SQL Server; PostgreSQL uses POSIX regular expressions (~, !~, or SIMILAR TO).

Interactive Query Terminals

Explore production-grade implementations of SQL wildcards running against active relational tables (customers, accounts, employees, branches, and transactions):

Query 1: Prefix Pattern Search (Al%) 
-- Prefix wildcard: Find all customers whose first name begins with 'Al'
SELECT customer_id, first_name, last_name, city, email
FROM customers
WHERE first_name LIKE 'Al%'
ORDER BY customer_id ASC;

Prefix Pattern Search Breakdown

Auditing the execution logic and relational mechanics of this query:

  • Applies The Prefix: Applies the prefix pattern 'Al%' to find clients whose given names begin with 'Al' (e.g. Alice, Alexander).
  • Leverages Index: Leverages B-Tree index seek capability because the prefix is fixed and known at query compile time.
  • Target Directory: Seamlessly pulls matching profiles from the verified customers registry.

Query 2: Infix Substring Matching (%Transfer%) 
-- Infix wildcard: Find all transactions mentioning 'Transfer' anywhere in description
SELECT transaction_id, account_id, transaction_type, amount, description
FROM transactions
WHERE description LIKE '%Transfer%'
ORDER BY amount DESC;

Infix Substring Matching Breakdown

Auditing the execution logic and relational mechanics of this query:

  • Encloses 'Transfer': Encloses 'Transfer' between two % wildcards, matching the token anywhere in the ledger memo.
  • Ledger Auditing: Isolates inter-account movements, wire transfers, and disbursals.
  • Descending Value: Orders matches by amount descending to spotlight high-value capital transfers.

Query 3: Single-Character Positional Pattern (___ah) 
-- Single-character positional wildcard: Find employees with 5-letter first names ending in 'ah'
SELECT employee_id, first_name, last_name, department, salary
FROM employees
WHERE first_name LIKE '___ah';

Positional Pattern Matching Breakdown

Auditing the execution logic and relational mechanics of this query:

  • Uses Exactly: Uses exactly three underscores (___) followed by ah, strictly enforcing a 5-character string length.
  • Prevents longer names (e.g. Abdullah or Deborah) from matching while requiring the exact suffix.
  • Pinpoints Sarah: Pinpoints Sarah Jenkins ($88,000.00) in the Engineering department.

Query 4: Suffix Pattern Search (%ar) 
-- Suffix wildcard: Find customers with surnames ending in 'ar' (e.g., Kumar, Prashar)
SELECT customer_id, first_name, last_name
FROM customers
WHERE last_name LIKE '%ar' AND customer_id <= 30;

Suffix Pattern Search Breakdown

Auditing the execution logic and relational mechanics of this query:

  • Employs The: Employs the suffix pattern '%ar' to locate client accounts whose surname concludes with 'ar'.
  • Combines Wildcard: Combines wildcard filtering with primary key bounds (customer_id <= 30) for efficient sampling.
  • Matches 8: Matches 8 accounts, led by Mrinal Prashar and Ripunjay Kumar.

Core Concepts & Engine Mechanics

Understanding the full catalog of wildcards across relational database engines ensures correct query design.

Wildcard Symbol Name Engine Support Pattern Meaning Example Match
% Percent Universal (All RDBMS) Zero, one, or multiple characters 'Sm%' matches 'Smith', 'Small'
_ Underscore Universal (All RDBMS) Exactly one single character 'h_t' matches 'hat', 'hot', 'hit'
[char_list] Character Set SQL Server / Sybase Any single character in set / range '[b-d]at' matches 'bat', 'cat'
[^char_list] Negated Set SQL Server / Sybase Any single character NOT in set '[^a]at' matches 'bat', not 'aat'
ESCAPE 'x' Escape Operator Universal ANSI Standard Treats following wildcard as literal '%50!%%' ESCAPE '!' matches '50%'

Index SARGability (Search Argument Ability)

Database query optimizers treat wildcard queries very differently depending on where the wildcard character appears:

  • SARGable (Fast Index Seek): WHERE name LIKE 'Tech%'. The database uses B-Tree index ordering to jump directly to entries starting with 'Tech' and reads sequentially.
  • Non-SARGable (Slow Full Table Scan): WHERE name LIKE '%Tech' or WHERE name LIKE '%Tech%'. The database cannot determine starting characters and must read every row sequentially.
  • Full-Text Search Alternative: For heavy infix searching on large tables, implement Full-Text Search (FTS) indexes (e.g. CONTAINS in SQL Server or to_tsvector in PostgreSQL) instead of wildcards.

Real-World Practical Scenario

Cross-Table Wire Transfer Pattern Search: Find all settled wire transfers and disbursals across customer accounts and the compliance ledger.

Production Query: Multi-Table Wire Transfer Search 
-- Combined wildcard search across joined tables
SELECT 
    t.transaction_id,
    c.first_name,
    c.last_name,
    a.account_type,
    t.description,
    t.amount
FROM transactions t
INNER JOIN accounts a ON t.account_id = a.account_id
INNER JOIN customers c ON a.customer_id = c.customer_id
WHERE t.description LIKE '%Wire%' AND t.status = 'Completed'
ORDER BY t.amount DESC;

Wire Transfer Search Breakdown

Auditing the execution logic and relational mechanics of this query:

  • Three-Way Join: Joins ledger transactions to deposit accounts and customer master profiles.
  • Matches High-Value Wires: Matches descriptions containing the keyword %Wire%.
  • Completed Funds Only: Restricts results to completed wire transfers for AML compliance auditing.

Best Practices & Production Guidelines

  • Anchor Prefixes Whenever Possible: Favor prefix matching ('ABC%') over infix matching ('%ABC%') to maintain sub-second index seek speeds on massive million-row datasets.
  • Be Careful with Underscore Counts: Every underscore represents exactly one character; verify character length requirements before applying multi-underscore filters.

Chapter Summary

SQL wildcards provide flexible character substitution capabilities for searching unstructured text fields, with distinct performance trade-offs based on index usage.

  • The % Symbol: Matches any sequence of zero, one, or multiple characters.
  • The _ Symbol: Matches exactly one character at a precise string position.
