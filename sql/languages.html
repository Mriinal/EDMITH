The 5 SQL Languages (DDL, DML, DQL, TCL, DCL)

18 Min Read • Core Foundation

Why is SQL Divided into 5 Sub-Languages?

When working with relational database systems, different tasks require different kinds of authority and functionality. Writing queries is not just about retrieving records; developers must build tables, insert records, manage transactional integrity, and configure user permissions.

To organize these distinct responsibilities, SQL is partitioned into five specialized sub-languages: DDL, DML, DQL, TCL, and DCL. Each group targets a specific operational layer of the database engine.

The Construction & Building Analogy

1. DDL (The Architect & Builder): Designs and builds the empty rooms, hallways, and walls (Database Schema, Tables, Columns).

2. DML (The Residents & Movers): Moves furniture in and out, redecorates rooms, or cleans items out (Rows and Data Records).

3. DQL (The Inspector / Visitor): Looks through the building and takes notes on what is inside without changing anything (Querying data).

4. TCL (The Legal Notary): Signs the lease contract permanently or cancels the deal if a mistake occurs (Commit & Rollback transactions).

5. DCL (The Security Guard): Hands out keycards and grants or revokes access to specific rooms (User permissions & privileges).

1. DDL — Data Definition Language

Data Definition Language (DDL) consists of commands that define, create, and alter the fundamental blueprint (schema) of database objects such as tables, schemas, views, and indexes. DDL commands change the structure of the database, not the individual records inside them.

Important Rule: DDL operations are auto-committed in almost all relational database engines (like MySQL, Oracle, and SQL Server). Once executed, they cannot be rolled back with a ROLLBACK command!

The core DDL commands are:

  • CREATE: Builds a new database, table, view, or index.
  • ALTER: Modifies an existing table structure (adding columns, modifying datatypes, adding constraints).
  • DROP: Permanently deletes an entire database object (structure and data) from disk.
  • TRUNCATE: Deletes all rows from a table rapidly while preserving the empty table structure.
  • RENAME: Changes the name of an existing table or column.
-- DDL Example: Defining a new student table and altering its schema
CREATE TABLE students (
    student_id INT PRIMARY KEY,
    first_name VARCHAR(50) NOT NULL,
    email VARCHAR(100) UNIQUE,
    enrollment_date DATE DEFAULT (CURRENT_DATE)
);

-- Add a new column to the existing table
ALTER TABLE students 
ADD COLUMN graduation_year INT;

2. DML — Data Manipulation Language

Data Manipulation Language (DML) operates on the data records (rows) stored inside existing database tables. When an application adds a new user, updates an account password, or deletes an outdated record, it executes DML statements.

Transactional Safety: DML commands are not auto-committed by default in standard transactions. Any DML modification can be inspected, tested, and safely rolled back using ROLLBACK before saving permanently with COMMIT.

The core DML commands are:

  • INSERT: Adds one or more new rows into a specified table.
  • UPDATE: Modifies values in existing rows based on a WHERE condition.
  • DELETE: Removes specific rows that match a WHERE condition.
-- DML Example: Populating and modifying student records
INSERT INTO students (student_id, first_name, email, graduation_year)
VALUES (101, 'Aarav', 'aarav@edmith.com', 2027);

-- Update student details
UPDATE students 
SET email = 'aarav.kumar@edmith.com' 
WHERE student_id = 101;

-- Remove an inactive student
DELETE FROM students 
WHERE student_id = 101;

3. DQL — Data Query Language

Data Query Language (DQL) is dedicated entirely to searching, filtering, and reading data from database tables without changing either the records or the schema.

DQL consists of one command with immense expressive power:

  • SELECT: Retrieves filtered, sorted, aggregated, and joined data sets from one or multiple tables.
-- DQL Example: Fetching specific data with conditions and sorting
SELECT student_id, first_name, email 
FROM students 
WHERE graduation_year >= 2026
ORDER BY first_name ASC;

4. TCL — Transaction Control Language

Transaction Control Language (TCL) statements manage database transactions. A transaction represents a bundle of SQL statements executed as a single, indivisible logical unit of work. TCL ensures that enterprise databases maintain strict ACID compliance.

The core TCL commands are:

  • COMMIT: Permanently saves all changes executed during the current transaction to disk.
  • ROLLBACK: Reverts all modifications made during the transaction back to the last committed state.
  • SAVEPOINT: Creates an intermediate checkpoint within a transaction, allowing partial rollbacks.
-- TCL Example: Secure banking transfer transaction
START TRANSACTION;

UPDATE accounts SET balance = balance - 500 WHERE account_no = 'ACC_1';
SAVEPOINT deduction_done;

UPDATE accounts SET balance = balance + 500 WHERE account_no = 'ACC_2';

-- If everything succeeded without errors:
COMMIT;

-- Or in case of failure:
-- ROLLBACK TO SAVEPOINT deduction_done;

5. DCL — Data Control Language

Data Control Language (DCL) governs the security and permissions of the database system. Database administrators (DBAs) use DCL statements to dictate which users or application services can read, insert, update, or administer specific database objects.

The core DCL commands are:

  • GRANT: Gives specified users access privileges to database tables or commands.
  • REVOKE: Takes away previously granted access privileges from a user.
-- DCL Example: Granting and revoking user privileges
GRANT SELECT, INSERT ON students TO 'analyst_user'@'localhost';

-- Revoke insertion capability when role changes
REVOKE INSERT ON students FROM 'analyst_user'@'localhost';

Interview Essential: DELETE vs TRUNCATE vs DROP

One of the most frequently asked questions in SQL and Data Engineering technical interviews revolves around the exact differences between these three deletion commands:

Feature DELETE (DML) TRUNCATE (DDL) DROP (DDL)
Language Type DML (Data Manipulation) DDL (Data Definition) DDL (Data Definition)
Operation Removes specific rows (using WHERE) Removes all rows from the table Deletes the entire table and schema
Rollback Support Yes (Can be rolled back) No (Auto-committed) No (Auto-committed)
Table Structure Structure remains intact Structure remains intact (empty) Structure is permanently destroyed
Speed Slower (logs row-by-row deletions) Extremely fast (deallocates data pages) Immediate deallocation

Master Summary of All 5 Languages

Category Full Name Primary Purpose Core Commands Auto-Commit
DDL Data Definition Language Defines & alters schema structure CREATE, ALTER, DROP, TRUNCATE, RENAME Yes
DML Data Manipulation Language Manages data records inside tables INSERT, UPDATE, DELETE No (Transactional)
DQL Data Query Language Retrieves & reads data records SELECT N/A (Read-only)
TCL Transaction Control Language Manages transactional boundaries COMMIT, ROLLBACK, SAVEPOINT Enforces state
DCL Data Control Language Controls user permissions & security GRANT, REVOKE Yes

Chapter Summary

Understanding the 5 sub-languages of SQL (DDL, DML, DQL, TCL, and DCL) is fundamental to designing, securing, and maintaining robust relational databases. Each sub-language serves a dedicated lifecycle role, from architecting schemas and querying records to managing transactional boundaries and access permissions.

  • DDL (Structure): Manages the database schema. Auto-committed operations like CREATE and ALTER cannot be reversed with rollback.
  • DML (Data): Operates on table records. Commands like INSERT, UPDATE, and DELETE can be safely rolled back in transactions.
  • DQL (Read): Centered around the SELECT statement, forming the backbone of all data analytics and reporting.
  • TCL (Safety): Ensures atomic execution through COMMIT and ROLLBACK, safeguarding data against system crashes.
  • DCL (Security): Enforces role-based access control with GRANT and REVOKE statements.
