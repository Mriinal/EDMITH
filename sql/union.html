The UNION Operator

15 Min Read • Module 1: Basics

The Merged Contact Address Book Analogy

Imagine combining contacts from two different smartphone address books into a single master contact list:

1. Address Book A (Personal Phone): Contains personal friends and family: Alice, Bob, Charlie.

2. Address Book B (Work Phone): Contains colleagues and clients: Bob, Diana, Edward.

3. The UNION Merge: You stack both lists into one master directory. Bob is in both books, but your master phone list records him once!

4. Schema Compatibility: Both address books must have compatible formats (Name, Phone Number) to be stacked together.

The UNION set operator combines result sets from multiple queries into a single dataset, automatically deduplicating identical rows.

Syntax & Statement Grammar

The standard SQL syntax and pattern rules for The UNION Operator:

SQL Syntax Grammar Blueprint 
SELECT column1, column2, ... column_n
FROM table1
[WHERE condition1]
UNION
SELECT column1, column2, ... column_n
FROM table2
[WHERE condition2]
[ORDER BY column1 [ASC | DESC]];

UNION Blueprint Breakdown

Core rules and architectural mechanics governing set union operations:

  • Vertical Set Stacking: Unlike joins which append columns horizontally, UNION appends result sets vertically row by row.
  • Identical Cardinality: Each participating SELECT statement must project the exact same number of columns in identical sequential order.
  • Type Compatibility: Corresponding columns in both queries must possess compatible data types (e.g., strings to strings, numerics to numerics).
  • Inherited Header Identifiers: The column names or aliases projected by the first SELECT query dictate the final column headers for the entire output.
  • Terminal ORDER BY: A single global ORDER BY clause may be appended at the end of the final query to sort the combined, deduplicated dataset.

Interactive Query Terminals

Explore production-grade implementations of UNION running against active relational tables (customers, employees, product_list, and sells_list):

Query 1: Cross-Entity Stakeholder Directory 
SELECT first_name, last_name, 'CUSTOMER' AS affiliation
FROM customers
WHERE customer_id <= 10
UNION
SELECT first_name, last_name, 'EMPLOYEE' AS affiliation
FROM employees
WHERE employee_id <= 10
ORDER BY first_name ASC;

Stakeholder Directory Breakdown

Auditing the cross-table vertical union operation:

  • Multi-Table Consolidation: Combines individuals from two structurally separate tables (customers and employees) into a consolidated master stakeholder registry.
  • Entity Lineage Badging: Injects synthetic string literals ('CUSTOMER' and 'EMPLOYEE') as an affiliation badge to preserve entity lineage.
  • Global Ordering: Applies a single sorting directive (ORDER BY first_name ASC) across the combined 20-row result set.

Query 2: Segmented Product Catalog Tiers 
SELECT product_id, product_name, category, price, 'PREMIUM' AS tier
FROM product_list
WHERE price >= 150.00
UNION
SELECT product_id, product_name, category, price, 'BUDGET' AS tier
FROM product_list
WHERE price < 50.00
ORDER BY price DESC;

Catalog Tier Segmentation Breakdown

Auditing disjoint price segment aggregation:

  • Disjoint Catalog Slicing: Extracts discrete business segments from product_list based on disparate pricing predicates (price >= 150.00 vs price < 50.00).
  • Segment Labeling: Appends matching inventory into a single categorized showcase, eliminating mid-tier items ($50 to $150).
  • Descending Valuation: The final unified dataset is sequenced from highest to lowest price via ORDER BY price DESC.

Query 3: Multi-Criteria VIP Account Qualification 
SELECT customer_id, 'HIGH_SINGLE_PURCHASE' AS qualification_reason
FROM sells_list
WHERE total_price >= 1000.00
UNION
SELECT customer_id, 'MULTIPLE_ORDERS' AS qualification_reason
FROM sells_list
GROUP BY customer_id
HAVING COUNT(*) >= 2
ORDER BY customer_id ASC;

VIP Account Qualification Breakdown

Auditing multi-criteria set union mechanics:

  • Disparate Query Unioning: Demonstrates unioning a row-filtered query (total_price >= 1000.00) with an aggregated grouped query (HAVING COUNT(*) >= 2).
  • Dual-Reason Inclusion: Allows a customer qualifying under both distinct criteria to appear with each corresponding qualification tag.
  • Segment Assembly: Demonstrates the power of set operators in assembling complex marketing audience segments without convoluted joins.

Query 4: Unique Stakeholder Population Metric 
SELECT COUNT(*) AS total_unique_stakeholders
FROM (
    SELECT first_name, last_name FROM customers
    UNION
    SELECT first_name, last_name FROM employees
) AS unique_people;

Stakeholder Population Breakdown

Auditing subquery aggregation across set operations:

  • Derived Table Wrapping: Embeds a UNION query within a subquery derived table (unique_people).
  • Automatic Deduplication: Because UNION automatically purges duplicate full name pairs, the outer COUNT(*) computes the true count of unique individuals across both databases.
  • Holistic Headcount: This pattern is critical for computing deduplicated reach, unique app visitors, and holistic organizational headcount.

Core Concepts & Engine Mechanics

The UNION operator evaluates separate SELECT statements and combines their result sets into a single tabular output while strictly discarding duplicate tuples.

Set Operation Duplicate Handling Underlying Algorithm Memory / CPU Overhead Ideal Use Case
UNION Removes duplicate rows automatically Sorts or builds hash table across all rows Higher (Requires sort/hash buffer) Merging overlapping customer rosters or unique identity catalogs
UNION ALL Preserves every duplicate row Direct streaming concatenation Minimal (Zero sorting or hashing) Partitioned transaction logs, disjoint monthly sales archives
INTERSECT Returns only rows present in BOTH queries Hash or sort intersection Moderate Finding customers who bought in both online and retail stores
EXCEPT / MINUS Returns rows in query 1 NOT in query 2 Hash anti-join Moderate Detecting churned customers or uncontacted newsletter leads

UNION vs UNION ALL: The Senior Performance Tradeoff

The choice between UNION and UNION ALL is one of the most critical performance optimizations in production database engineering:

  • The Deduplication Penalty: To eliminate duplicates, the database engine must buffer rows, execute an in-memory hash or external disk sort, and compare column tuples.
  • When Deduplication is Unnecessary: If queries draw from mutually exclusive partitions (such as WHERE sale_date LIKE '2024%' vs WHERE sale_date LIKE '2025%'), duplicates are mathematically impossible. Running UNION wastes compute power.
  • Golden Rule: Always default to UNION ALL unless business requirements explicitly dictate deduplication across datasets.

Real-World Practical Scenario

Omnichannel Customer & Employee Directory: Synthesize the customer database and employee staff roster into an active unified communication contact directory, categorized with role badges.

Production Query: Enterprise Unified Directory 
SELECT customer_id AS account_id, first_name, last_name, 'CLIENT' AS account_role
FROM customers
WHERE customer_id <= 5
UNION
SELECT employee_id AS account_id, first_name, last_name, 'INTERNAL_STAFF' AS account_role
FROM employees
WHERE employee_id <= 5
ORDER BY account_id ASC;

Enterprise Directory Breakdown

Auditing production directory synthesis:

  • Key Normalization: Harmonizes different entity keys under a clean unified alias: customer_id AS account_id and employee_id AS account_id.
  • Projection Precedence: Demonstrates that column aliases in subsequent SELECT statements do not alter the column names defined by the initial query.
  • Schema Integrity: Guarantees strict schema integrity while providing an omnichannel reporting view for executive dashboards.

Best Practices & Production Guidelines

  • Explicit Column Selection: Never use SELECT * UNION SELECT * in production; schema migrations that alter column order or add columns will corrupt query output or cause runtime failures.
  • Validate Data Types: Ensure matching columns share compatible data types. Avoid forcing the database into expensive implicit type casting.
  • Benchmark Deduplication Needs: Switch to The UNION ALL Operator whenever inputs are guaranteed distinct to eliminate sorting overhead.
  • Global Ordering: Remember that ORDER BY belongs only after the final SELECT statement.

Chapter Summary

The UNION operator provides vertical set stacking across independent queries, automatically purging duplicate records and enforcing relational schema alignment.

  • Automatic Deduplication: Eliminates duplicate rows across combined query results.
  • Schema Alignment: Requires identical column counts and compatible data types.
