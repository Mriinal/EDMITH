FULL OUTER JOIN

15 Min Read • Module 1: Basics

The Corporate Merger Audit Analogy

Two merging banks combine their client rosters. Bank A has clients that Bank B doesn't have, and Bank B has clients that Bank A doesn't have. The auditor needs a master spreadsheet listing every single client from both banks, showing who had accounts where.

FULL OUTER JOIN preserves all rows from both tables, padding NULLs in whichever table lacked a match.

Syntax & Statement Grammar

The standard SQL syntax and clause requirements for FULL OUTER JOIN:

SQL Grammar • full-join.sql 
SELECT columns
FROM table_a
FULL OUTER JOIN table_b ON table_a.key = table_b.key;

Core Concepts & Engine Mechanics

FULL OUTER JOIN combines the results of both LEFT JOIN and RIGHT JOIN. It returns all records from both tables, with NULL values where the join condition does not match.

In databases like MySQL that lack native FULL OUTER JOIN syntax, you can achieve the exact same result by combining a LEFT JOIN and a RIGHT JOIN using UNION.

Real-World Practical Scenario

Reconciling Partner Accounts and Master Customers: Produce a master reconciliation report showing matched and unmatched records on both sides.

Production Example • Reconciling Partner Accounts and Master Customers 
SELECT 
    c.customer_id, 
    c.email AS internal_email,
    p.partner_client_id,
    p.email AS partner_email
FROM internal_customers c
FULL OUTER JOIN partner_clients p ON c.tax_id = p.tax_id;

Chapter Summary

FULL OUTER JOIN merges the complete contents of both tables, retaining all records regardless of whether a matching relationship exists. It is the premier tool for database synchronization and reconciliation audits.

  • Bidirectional Preservation: Returns all rows from both tables, with NULLs on either side when no match exists.
  • Reconciliation Auditing: Ideal for financial reconciliation, data migration audits, and master index syncs.
  • MySQL Workaround: Simulate in MySQL by unioning a LEFT JOIN and a RIGHT JOIN.
  • Symmetric Difference: Filter WHERE a.id IS NULL OR b.id IS NULL to isolate rows that exist in only one table.
