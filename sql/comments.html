SQL Comments

15 Min Read • Module 1: Basics

The Architectural Blueprint Sticky Note Analogy

Picture a structural civil engineer reviewing the blueprint schematics for a 60-story skyscraper:

  • 1. The Construction Lines:: The structural walls, steel beams, and electrical conduits are formal construction directives executed by builders.
  • 2. The Yellow Sticky Note (Comment):: The lead architect attaches a yellow note: 'Reinforced concrete required here due to high seismic activity.'
  • 3. Invisible to Concrete Pourers:: The sticky note does not add physical steel or concrete to the building; it informs future inspectors why the beam is reinforced.
  • 4. Zero Structural Cost:: The note adds zero weight to the building, but saves the next engineering team weeks of confusion during future renovations.

SQL comments document code intent, business logic, and analytical assumptions for developer collaboration, carrying zero runtime execution cost.

Core Concepts & Engine Mechanics

SQL comments are explanatory notes authored by developers to document code intent, explain complex algorithms, and temporarily disable code blocks during debugging. Comments are stripped out by the database lexer during query parsing and have zero impact on execution speed.

  • Single-Line Comments (--): Two consecutive hyphens (--) instruct the parser to ignore everything from the hyphens to the end of that physical line.
  • Multi-Line Comments (/* */): Characters between /* and */ are ignored across multiple lines, ideal for query header documentation.
  • Zero Runtime Overhead: The database parser discards comments in microseconds during the lexical analysis tokenization phase; comments do not affect query execution time.
  • Optimizer Hints: Some database engines (Oracle, MySQL) support special comment syntax (e.g. /*+ INDEX(t idx_name) */) to pass directives to the query optimizer.

Detailed Technical Breakdown & Syntax Comparison

Comment Type Syntax Marker Span Scope Ignored by Engine? Common Use Case
Single-Line -- comment text Rest of line Yes (Discarded by lexer) Explaining specific column filters
Multi-Line Block /* comment text */ Multiple lines Yes (Discarded by lexer) File header docs, JIRA ticket notes
Inline Comment col -- note End of code line Yes Explaining business constants (tax rates)
Optimizer Hint /*+ HINT */ Engine-specific No (Parsed by optimizer) Forcing index seeks or hash joins

Database Optimizer Hints Inside Comments

While standard comments are stripped out by parsers, specialized comment markers can be used to pass hints to query optimizers:

  • The Oracle / MySQL Hint Syntax: Comments beginning with a plus sign (/*+ ... */) are treated as optimizer directives rather than plain comments.
  • Example: SELECT /*+ INDEX(employees idx_emp_salary) */ * FROM employees WHERE salary > 100000; instructs the engine to use that specific index.
  • Caution: Optimizer hints should be used sparingly; modern cost-based query optimizers generally make superior plan choices based on real-time statistics.

Chapter Summary

SQL comments document code intent, business rules, and analytical assumptions for developer collaboration, carrying zero runtime execution cost.

  • Single-Line Syntax: Use two hyphens (--) to comment out single lines or provide inline column explanations.
  • Multi-Line Syntax: Use /* ... */ to encapsulate multi-line header documentation, authorship tags, and changelogs.
  • Zero Performance Cost: Comments are stripped out by the database parser in microseconds during lexical analysis.
  • Debugging Aid: Use comments to temporarily disable clauses or expressions during troubleshooting.
  • Optimizer Hints: Be aware that specialized comments (/*+ HINT */) pass directives to database query planners.
