The UNION Operator

15 Min Read • Module 1: Basics

The Merged Contact Address Book Analogy

Imagine combining contacts from two different smartphone address books into a single master contact list:

  • 1. Address Book A (Personal Phone):: Contains family and close friends: Alice, Bob, Charlie.
  • 2. Address Book B (Work Phone):: Contains colleagues and professional contacts: Bob, Diana, Edward.
  • 3. The UNION Merge:: You stack both lists into one master directory. Bob is in both books, but your master phone list records him once!
  • 4. Schema Compatibility:: Both address books must have compatible formats (Name, Phone Number) to be stacked together.

The UNION set operator combines result sets from multiple queries into a single dataset, automatically deduplicating identical rows.

The standard SQL syntax and pattern rules for The UNION Operator:

FROM retail_customers
UNION

Core Concepts & Engine Mechanics

The UNION operator combines the result sets of two or more SELECT statements into a single unified result set. It automatically performs row deduplication, removing duplicate records across the combined outputs.

  • Column Alignment Rules: Every query in the UNION must have the exact same number of projected columns in identical sequence, and data types must be compatible.
  • Automatic Deduplication Cost: UNION performs an expensive sort or hash operation across the entire combined dataset to detect and discard duplicates.
  • Column Headers from First Query: The column aliases and header labels of the final output are determined exclusively by the first SELECT statement.
  • Single Global ORDER BY: Individual queries cannot have their own ORDER BY clauses; a single ORDER BY placed at the very end sorts the combined final dataset.

Detailed Technical Breakdown & Syntax Comparison

Set Operation Duplicate Handling Underlying Algorithm Memory / CPU Overhead Ideal Use Case
UNION Removes duplicate rows automatically Sorts or builds hash table across all rows Higher (Requires sort/hash buffer) Merging overlapping customer lists
UNION ALL Preserves every duplicate row Direct streaming concatenation Minimal (Zero sorting or hashing) Partitioned logs, unioning disjoint tables
INTERSECT Returns only rows present in BOTH queries Hash or sort intersection Moderate Finding shared customers between apps
EXCEPT / MINUS Returns rows in query 1 NOT in query 2 Hash anti-join Moderate Customer churn, list subtraction

UNION vs UNION ALL: The Senior Performance Tradeoff

The difference between UNION and UNION ALL is one of the most critical performance optimizations in SQL engineering:

  • The Performance Overhead: UNION requires the database engine to sort millions of rows in memory (or spill to disk temporary files) to eliminate duplicates.
  • When Deduplication is Pointless: If query 1 selects WHERE year = 2025 and query 2 selects WHERE year = 2026, duplicates are mathematically impossible!
  • The Best Practice: Always default to UNION ALL unless business requirements strictly dictate deduplication.

Chapter Summary

The UNION set operator stacks the results of multiple independent queries into a unified, deduplicated dataset, enforcing schema alignment and relational uniqueness.

  • Automatic Deduplication: UNION automatically removes duplicate identical rows across combined queries.
  • Schema Compatibility: All joined queries must return the same number of columns with compatible data types in identical order.
  • First Query Header Naming: Column names and aliases in the final output are determined by the first SELECT statement.
  • Single Terminal ORDER BY: Place a single ORDER BY at the very end of the final query to sort the combined result set.
  • Default to UNION ALL: If duplicates are impossible or acceptable, use UNION ALL to avoid the heavy CPU/RAM sorting overhead of UNION.
