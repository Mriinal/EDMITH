The BETWEEN Operator

15 Min Read • Module 1: Basics

The Highway Vehicle Weigh Station Analogy

Picture a highway commercial vehicle inspection weigh station monitoring freight trucks:

  • 1. The Lower Boundary (Inclusive):: Trucks weighing 10,000 lbs or more must enter the inspection lane (weight >= 10000).
  • 2. The Upper Boundary (Inclusive):: Trucks weighing up to 26,000 lbs qualify for standard commercial class (weight <= 26000).
  • 3. The Inclusive BETWEEN Window:: The rule: BETWEEN 10000 AND 26000. Exactly 10,000 lbs and exactly 26,000 lbs are BOTH included inside the boundary!
  • 4. Boundary Inversion:: Trucks NOT BETWEEN 10,000 and 26,000 are diverted to special light-duty or heavy-overweight lanes.

The BETWEEN operator filters metrics within an inclusive lower and upper boundary, streamlining numerical ranges and date intervals.

Syntax & Statement Grammar

The standard SQL syntax and pattern rules for The BETWEEN Operator:

SQL Syntax Grammar • between.sql 
-- 1. Numeric Range Filtering (Inclusive of Boundaries)
SELECT product_id, product_name, unit_price
FROM store_products
WHERE unit_price BETWEEN 50.00 AND 150.00;

-- 2. Chronological Date Filtering
SELECT order_id, customer_id, order_date, total_amount
FROM sales_orders
WHERE order_date BETWEEN '2026-01-01' AND '2026-03-31';

-- 3. Alphabetical Text Range Filtering
SELECT employee_id, first_name, last_name
FROM employees
WHERE last_name BETWEEN 'Adams' AND 'Miller';

-- 4. Inverting the Interval with NOT BETWEEN
SELECT student_id, exam_score
FROM examination_results
WHERE exam_score NOT BETWEEN 60 AND 80;

Core Concepts & Engine Mechanics

The BETWEEN operator tests whether an expression falls within an inclusive specified range. The syntax expression BETWEEN low AND high is semantically identical to expression >= low AND expression <= high.

  • Inclusive Boundaries Rule: BETWEEN is strictly inclusive on both ends; values that exactly match either boundary are included in the result set.
  • Order of Operands: The lower boundary must be declared first; writing BETWEEN 100 AND 50 returns zero rows because no value can be >= 100 and <= 50 simultaneously.
  • Timestamp Truncation Trap: Filtering timestamps with BETWEEN '2026-01-01' AND '2026-01-31' cuts off at midnight 2026-01-31 00:00:00, missing transactions later that day!
  • Index Range Scans: BETWEEN operations on indexed columns leverage efficient B-Tree Index Range Scans.

Detailed Technical Breakdown & Syntax Comparison

Data Type Syntax Pattern Equivalent SQL Expression Boundary Inclusivity Common Gotcha
Numeric (INT / DECIMAL) WHERE price BETWEEN 10 AND 50 price >= 10 AND price <= 50 Includes 10 and 50 Inverting low/high returns 0 rows
Date (DATE) WHERE d BETWEEN '2026-01-01' AND '2026-01-31' d >= '2026-01-01' AND d <= '2026-01-31' Includes both end dates Safe for pure DATE types
Timestamp (DATETIME) WHERE ts BETWEEN '2026-01-01' AND '2026-01-31' ts >= '2026-01-01' AND ts <= '2026-01-31 00:00:00' Cuts off at midnight! Misses hours on final day
Text (VARCHAR) WHERE name BETWEEN 'A' AND 'M' name >= 'A' AND name <= 'M' Includes 'A' up to 'M' Excludes 'Miller' (comes after 'M')

The Timestamp Midnight Trap with BETWEEN

The most pervasive reporting error in SQL occurs when querying DATETIME or TIMESTAMP columns using BETWEEN:

  • The Flawed Query: WHERE order_timestamp BETWEEN '2026-01-01' AND '2026-01-31' expands to order_timestamp <= '2026-01-31 00:00:00'.
  • The Missed Revenue: An order placed at 2026-01-31 14:30:00 is completely excluded from the month-end report!
  • The Best Practice Fix: Always use explicit half-open intervals: WHERE order_timestamp >= '2026-01-01' AND order_timestamp < '2026-02-01';.

Real-World Practical Scenario

Corporate Performance Bonus & Compensation Review: Audit enterprise compensation brackets and performance review scoring tiers for quarterly merit increases.

Production Queries • Corporate Performance Bonus & Compensation Review 
/* ========================================================
   Sample Dataset: employee_compensation
   emp_id | full_name       | department    | base_salary | rating_score | hire_date
   -------+-----------------+---------------+-------------+--------------+------------
   101    | Marcus Cole     | Engineering   | 85000.00    | 4.2          | 2024-03-15
   102    | Susan Ivanova   | Operations    | 72000.00    | 3.8          | 2025-06-01
   103    | John Sheridan   | Executive     | 130000.00   | 4.9          | 2023-01-10
   104    | Stephen Franklin| Medical       | 95000.00    | 4.5          | 2024-08-20
   105    | Michael Garibaldi| Security     | 68000.00    | 3.4          | 2025-11-05
   ======================================================== */

-- Requirement 1: Isolate employees in the mid-tier salary band ($70,000 to $95,000)
SELECT emp_id, full_name, base_salary
FROM employee_compensation
WHERE base_salary BETWEEN 70000.00 AND 95000.00;
-- Matches: Susan ($72,000), Marcus ($85,000), Stephen ($95,000 - boundary included)

-- Requirement 2: Target high-performance ratings between 4.0 and 5.0 for bonus pool
SELECT emp_id, full_name, rating_score, department
FROM employee_compensation
WHERE rating_score BETWEEN 4.0 AND 5.0;
-- Matches: Marcus (4.2), Stephen (4.5), John (4.9)

-- Requirement 3: Identify staff hired during the 2024 calendar year
SELECT emp_id, full_name, hire_date
FROM employee_compensation
WHERE hire_date BETWEEN '2024-01-01' AND '2024-12-31';
-- Matches: Marcus Cole (2024-03-15) and Stephen Franklin (2024-08-20)

-- Requirement 4: Isolate salary outliers falling outside standard range with NOT BETWEEN
SELECT emp_id, full_name, base_salary
FROM employee_compensation
WHERE base_salary NOT BETWEEN 70000.00 AND 100000.00;
-- Matches outliers: Michael ($68,000 - below) and John ($130,000 - above)

Chapter Summary

The BETWEEN operator filters metrics within an inclusive lower and upper boundary, providing concise and readable interval checking across numbers, dates, and text.

  • Inclusive on Both Ends: BETWEEN includes both the lower and upper threshold values in the evaluated range.
  • Operand Ordering: Always specify the lower boundary first; low AND high (e.g. BETWEEN 10 AND 50).
  • The Timestamp Midnight Trap: For DATETIME or TIMESTAMP attributes, prefer half-open intervals (>= start AND < end) over BETWEEN to avoid missing end-day records.
  • Index Range Scans: B-Tree indexes can satisfy BETWEEN queries efficiently using index range scans.
  • Negative Ranges: Use NOT BETWEEN to identify outlier records falling outside approved operational thresholds.
