The UNION ALL Operator

15 Min Read • Module 1: Basics

The Dual Cash Register Cash Drop Analogy

Imagine a bustling coffee shop with two cash registers operating side by side during morning rush hour:

  • 1. Register A Envelope:: Register 1 records twenty $5 bills and ten $20 bills in an envelope.
  • 2. Register B Envelope:: Register 2 records fifteen $5 bills and eight $20 bills in another envelope.
  • 3. The Nightly Deposit (UNION ALL):: The manager dumps both envelopes into the bank deposit bag. They do NOT discard duplicate $5 bills! Every single physical bill must be deposited.
  • 4. High-Speed Pipeline:: Pouring the envelopes together takes 2 seconds because no one wastes time checking for duplicate serial numbers.

UNION ALL concatenates multiple query results directly without the CPU sorting overhead of deduplication, preserving every single row.

Syntax & Statement Grammar

The standard SQL syntax and pattern rules for The UNION ALL Operator:

Query 1: Data Projection & Extraction 
SELECT transaction_id, customer_id, amount, 'POS_TERMINAL_1' AS source
FROM terminal_1_sales
UNION ALL
SELECT transaction_id, customer_id, amount, 'POS_TERMINAL_2' AS source
FROM terminal_2_sales;

Core Concepts & Engine Mechanics

The UNION ALL operator combines the result sets of two or more SELECT statements without removing duplicate rows. Because it skips the sorting and hashing phase required for deduplication, it delivers peak query throughput.

  • Complete Row Preservation: If an identical record appears 3 times in Query A and 2 times in Query B, UNION ALL outputs that record exactly 5 times.
  • Peak I/O Performance: Executes as a simple streaming concatenation; the database engine pipelines rows directly to the client without buffering or sorting.
  • Partitioned Table Standard: UNION ALL is the foundational building block for partitioned views and Big Data distributed table scans.
  • Column Matching Constraints: Like standard UNION, all chained queries must project the same number of columns with compatible data types.

Why Production Codebases Mandate UNION ALL by Default

Senior database administrators frequently enforce a strict linting rule: 'Never write UNION when UNION ALL is sufficient':

  • The Memory Hazard: Running UNION across two 5-million row tables forces the query optimizer to allocate huge memory buffers or spill 10GB of temporary files to disk to perform deduplication sorting.
  • The Streaming Advantage: UNION ALL begins returning the first rows to the API caller in milliseconds because no sorting barrier exists.
  • Golden Rule: Only use plain UNION if duplicate rows would cause business logic failures or financial reporting errors.

Real-World Practical Scenario

Enterprise Microservice Distributed Log Aggregator: Stream and synthesize application event telemetry across independent microservice cluster logging tables into a single real-time observability feed.

Chapter Summary

UNION ALL concatenates multiple query results without the expensive CPU sorting overhead of deduplication, providing maximum streaming throughput across enterprise datasets.

  • Preserves All Duplicates: Retains every single row returned by each query without deduplication.
  • Maximum Performance: Zero sorting or hashing overhead; streams rows directly to the client with minimal memory usage.
  • Partitioned Table Workhorse: The standard tool for querying partitioned historical tables and distributed log streams.
  • Schema Alignment Required: Chained queries must match in column count and data type compatibility.
  • Default Choice: Always prefer UNION ALL over UNION unless business requirements strictly mandate duplicate removal.
