SQL Operators Reference

15 Min Read • Module 3: References

The Swiss Army Toolkit Operator Analogy

Picture a master engineer carrying a versatile multi-compartment Swiss Army toolkit into a maintenance hangar:

1. Arithmetic Instruments: Calipers, rulers, and scales perform calculations on raw numeric values: Addition (+), Subtraction (-), Multiplication (*), Division (/), and Modulo (%).

2. Comparison Gauges: Go/no-go gauges check whether machine parts fit exact tolerances: Equal (=), Not Equal (<> or !=), Greater Than (>), and Less Than (<).

3. Logical Interlocks: Multi-switch circuit interlocks evaluate compound states: AND, OR, NOT, BETWEEN, and IN.

4. Universal Assembly: Every SQL expression combines these fundamental tools to transform raw table data into structured analytical intelligence.

SQL operators provide the fundamental computational instruments for arithmetic calculations, equality comparisons, and boolean logic.

Companion Tutorials: Explore in-depth guides for individual operator families in The WHERE Clause, The AND Operator, The OR Operator, and The BETWEEN Operator.

Syntax & Statement Grammar

The standard SQL syntax and pattern rules for SQL Operators Reference:

SQL Syntax Grammar Blueprint 
-- 1. Arithmetic Operators (+, -, *, /, %)
SELECT (col1 * col2) + col3 AS total_calc, col1 % 10 AS remainder
FROM table_name;

-- 2. Comparison Operators (=, <>, !=, <, <=, >, >=)
SELECT * FROM table_name WHERE status = 'PAID' AND amount >= 500.00;

-- 3. Logical Operators (AND, OR, NOT, BETWEEN, IN, LIKE, IS NULL)
SELECT * FROM table_name WHERE category IN ('A', 'B') AND NOT (price < 50);

-- 4. String Concatenation Operator (||)
SELECT first_name || ' ' || last_name AS full_name FROM customers;

SQL Operators Blueprint Breakdown

Core rules and architectural mechanics governing arithmetic, comparison, and logical evaluation in relational engines:

  • Arithmetic Precedence: Multiplication (*), division (/), and modulo (%) evaluate before addition (+) and subtraction (-). Use parentheses () to enforce evaluation order.
  • Comparison Standards: ANSI SQL defines <> as the standard not-equal operator; virtually all modern engines also support !=.
  • Logical Evaluation Hierarchy: In boolean predicates without parentheses, NOT executes first, followed by AND, followed by OR.
  • Safe Division: To prevent fatal runtime division-by-zero errors, wrap divisors in NULLIF(divisor, 0), which yields NULL rather than crashing.

Interactive Query Terminals

Explore production-grade implementations of SQL operators running against active relational tables (loans, employees, customers, and branches):

Query 1: Arithmetic Computations & Term Modulo 
-- Arithmetic Operators: Multiplication (*), Division (/), Subtraction (-), and Modulo (%)
SELECT 
    loan_id,
    amount AS principal,
    interest_rate,
    term_months,
    ROUND(amount * (interest_rate / 100.0) / 12, 2) AS monthly_interest_cost,
    ROUND((amount / term_months) + (amount * (interest_rate / 100.0) / 12), 2) AS estimated_monthly_emi,
    term_months % 12 AS remaining_months_beyond_years
FROM loans
WHERE loan_id <= 10;

Arithmetic Computations Breakdown

Auditing the execution logic and relational mechanics of this query:

  • Calculates Interest Fractions: Computes monthly interest cost via multiplication and division (amount * (interest_rate / 100.0) / 12).
  • Estimates Monthly EMI: Combines principal amortization and monthly accrued interest.
  • Evaluates Term Remainder: Calculates non-annual remaining loan periods via modulo (term_months % 12).

Query 2: Comparison & Range Evaluation 
-- Comparison & Range Operators: >=, <>, BETWEEN, and IN
SELECT 
    employee_id,
    first_name,
    last_name,
    department,
    salary
FROM employees
WHERE salary >= 80000 
  AND department <> 'Human Resources'
  AND salary BETWEEN 75000 AND 120000;

Comparison & Range Evaluation Breakdown

Auditing the execution logic and relational mechanics of this query:

  • Combines Comparison: Combines comparison operators (>=, <>) with the range operator (BETWEEN).
  • Filters Out: Filters out Human Resources staff while restricting salary between $75,000 and $120,000.
  • Returns 8: Returns 8 qualifying senior staff and engineering managers.

Query 3: String Concatenation & Conditional Null Safe Logic 
-- String Concatenation (||) and NULL-Safe Logic
SELECT 
    customer_id,
    first_name || ' ' || last_name AS full_name,
    CASE 
        WHEN middle_name IS NOT NULL THEN first_name || ' ' || middle_name || ' ' || last_name
        ELSE first_name || ' ' || last_name
    END AS formal_name
FROM customers
WHERE customer_id <= 10;

String Concatenation Breakdown

Auditing the execution logic and relational mechanics of this query:

  • Uses The: Uses the ANSI standard string concatenation operator (||) to join string columns.
  • Protects Against: Protects against null concatenation artifacts using IS NOT NULL inside a CASE expression.
  • Constructs Formal: Constructs formal customer titles cleanly across account records.

Query 4: Compound Boolean Logic (AND, OR, NOT) 
-- Logical Operators: Combined Compound Predicates (AND, OR, NOT)
SELECT 
    loan_id,
    customer_id,
    loan_type,
    amount,
    interest_rate,
    status
FROM loans
WHERE (loan_type = 'Home Mortgage' OR loan_type = 'Business Expansion')
  AND NOT (status = 'Defaulted')
  AND amount >= 100000.00;

Compound Boolean Logic Breakdown

Auditing the execution logic and relational mechanics of this query:

  • Enforces Explicit Grouping: Enforces explicit priority grouping with parentheses (loan_type = 'Home Mortgage' OR loan_type = 'Business Expansion').
  • Applies Unary NOT: Applies the unary NOT operator to exclude delinquent accounts (NOT (status = 'Defaulted')).
  • Filters High-Value Facilities: Restricts records to institutional commitments with principal amount >= 100000.00.

Core Concepts & Engine Mechanics

A reference taxonomy of universal SQL operators across arithmetic, comparison, logical, and string domains:

Operator Category Symbols / Keywords Functionality Example Usage
Arithmetic +, -, *, /, % Numeric computation price * 1.08
Comparison =, <>, !=, <, <=, >, >= Value equality / ordering salary >= 75000
Range & Set BETWEEN ... AND, IN (...) Bounded range & discrete membership status IN ('PAID', 'PENDING')
Pattern & Null LIKE, NOT LIKE, IS NULL, IS NOT NULL String patterns & unknown checks middle_name IS NOT NULL
Logical AND, OR, NOT Boolean condition combining status = 'PAID' AND total > 100
String || (ANSI), + (T-SQL), CONCAT() String concatenation first_name || ' ' || last_name

Operator Precedence Order

When multiple operators appear in a single expression without parentheses, the database engine resolves them in strict hierarchy:

  • Level 1 (Highest): Parentheses ()
  • Level 2: Multiplication (*), Division (/), Modulo (%)
  • Level 3: Addition (+), Subtraction (-)
  • Level 4: Comparison operators (=, <>, <, >, BETWEEN, IN, LIKE)
  • Level 5: Logical NOT
  • Level 6: Logical AND
  • Level 7 (Lowest): Logical OR

Real-World Practical Scenario

Pricing Variance & Billing Reconciliation Pipeline: Calculate billing variance between catalog list prices and actual transaction totals across multi-table customer orders.

Production Query: Loan Portfolio Yield & First-Year Exposure Analysis 
-- Production Comprehensive Operator Pipeline: Relational Join with Arithmetic and Logical Filtering
SELECT 
    l.loan_id,
    c.first_name || ' ' || c.last_name AS borrower_name,
    b.branch_name,
    l.loan_type,
    l.amount AS facility_amount,
    l.interest_rate,
    ROUND(l.amount * (l.interest_rate / 100.0), 2) AS annual_interest_accrual,
    ROUND(l.amount + (l.amount * (l.interest_rate / 100.0)), 2) AS total_first_year_exposure
FROM loans l
INNER JOIN customers c ON l.customer_id = c.customer_id
INNER JOIN branches b ON l.branch_id = b.branch_id
WHERE l.status = 'Active'
  AND (l.amount >= 150000.00 OR l.interest_rate > 7.00)
ORDER BY l.amount DESC;

Loan Portfolio Yield Breakdown

Auditing the execution logic and relational mechanics of this query:

  • Combines Arithmetic: Combines arithmetic operators (*, /, +), string concatenation (||), and relational comparison (=, >=, >).
  • Quantifies Credit Exposure: Calculates annual interest yield and total balance commitment across active high-value facilities.
  • Demonstrates Institutional Modeling: Models comprehensive credit risk by joining loans, customers, and branches.

Best Practices & Production Guidelines

  • Always Use Parentheses for Clarity: Never rely on human memory for operator precedence; always use explicit parentheses (A AND B) OR C to avoid catastrophic logic bugs.
  • Protect Against Divide-by-Zero: Write ROUND(revenue / NULLIF(units, 0), 2) to gracefully return NULL rather than aborting batch jobs.

Chapter Summary

SQL operators form the fundamental computing language of relational queries, spanning arithmetic calculations, equality assertions, pattern matches, and complex boolean logic.

  • Precedence Rules: Parentheses take precedence over arithmetic, which takes precedence over logical AND/OR.
  • Universal Standards: ANSI standards ensure portability of comparison and logical operations across all modern engines.
