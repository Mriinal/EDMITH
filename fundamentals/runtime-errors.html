Runtime Errors & Exceptions

8 Min Read • Beginner • Language Agnostic

1. When Valid Code Crashes Mid-Execution

A runtime error occurs when a program that is syntactically completely valid encounters an operation that the computer hardware or operating system cannot physically or mathematically execute while the program is actively running.

Unlike syntax errors (which prevent the program from starting), runtime errors strike while the program is in progress. The operating system or runtime environment halts execution immediately, often generating a crash or an unhandled exception.

2. The Most Common Runtime Errors in Computing

Runtime Error Type Why the Hardware/OS Rejects It Real-World Scenario
Division by Zero Mathematically undefined; the CPU's Arithmetic Logic Unit triggers an arithmetic trap. Dividing invoice amount by user input where quantity entered was 0.
Null / Undefined Reference Attempting to read or write data through an address that points to empty memory. Reading user address before the user has loaded their profile.
Index Out of Bounds Requesting an element at an index outside the allocated boundaries of an array or list. Accessing element at index 10 in a list that contains only 5 items.
Stack Overflow Exhausting the allocated memory of the call stack through uncontrolled recursion. A function that calls itself repeatedly without an exit base condition.

3. Defensive Programming: Guarding Against Runtime Crashes

Professional software engineers practice defensive programming to anticipate potential runtime failures before they occur:

  • Input Validation: Never trust raw external input. Always verify that numbers are positive and non-zero before using them in division.
  • Boundary Checks: Confirm that an index is within valid ranges before attempting to access elements.
  • Null Checks: Verify that an object or record actually exists before referencing its properties.

4. Key Takeaways

  • Runtime errors happen during active program execution due to invalid operations.
  • Common causes include division by zero, null references, and out-of-bounds array access.
  • Runtime exceptions halt program execution unless defensively guarded.
  • Proactive input validation prevents the vast majority of runtime crashes.
