SQL Wildcards Reference

15 Min Read • Module 3: References

The Card Game Wildcard Joker Analogy

Picture playing a card game with a deck containing standard numbered cards and special wild Jokers:

  • 1. Standard Cards:: A regular card like the 7 of Spades represents strictly that exact card and nothing else.
  • 2. The Percent (%) Joker:: The % wildcard is like a magic chameleon card that can morph into an entire straight flush of any length, or vanish completely (zero characters).
  • 3. The Underscore (_) Single Joker:: The _ wildcard is a single wild card that must represent exactly one specific card position.
  • 4. Exact Replacement:: Combining fixed letters with Jokers lets you build flexible winning hands (patterns) without knowing every card in advance.

SQL wildcards substitute for arbitrary characters in text searches, allowing developers to craft prefix, suffix, and positional matching queries.

Beginner Tutorials: Learn how to apply these wildcard patterns in hands-on production queries with step-by-step examples in The LIKE Operator and The NOT Operator in Module 1.

Core Concepts & Engine Mechanics

SQL wildcards are specialized pattern-matching symbols used in conjunction with the LIKE and NOT LIKE operators. ANSI SQL defines two universal wildcard characters: the percent sign (%) and the underscore (_).

  • The Percent (%) Token: Represents zero, one, or any arbitrary sequence of multiple characters.
  • The Underscore (_) Token: Represents exactly one single character at that precise character position.
  • Escaping Special Characters: When querying strings that contain literal % or _ characters, declare an explicit ESCAPE character.
  • Database Variations: Some database engines (SQL Server, Access) provide bracketed sets like [a-z] or [^abc], while others (PostgreSQL) provide POSIX regular expressions (~).

Detailed Technical Breakdown & Syntax Comparison

Wildcard Symbol Pattern Example Match Mechanics Matching Values Index SARGable?
% (Suffix) LIKE 'Dev%' Starts with 'Dev', followed by any length Dev, Developer, DevOps Yes (B-Tree Index Seek)
% (Prefix) LIKE '%tion' Any characters ending with 'tion' Action, Solution, Nation No (Full Table Scan)
% (Infix) LIKE '%log%' Contains 'log' anywhere in the string Catalog, Blogger, Logic No (Full Table Scan)
_ (Single Pos) LIKE '_at' Exactly 3 letters ending in 'at' Cat, Hat, Bat, Rat No (Leading wildcard)
_ (Fixed Prefix) LIKE 'C_t' Starts with C, 1 arbitrary char, ends in t Cat, Cot, Cut Yes (Bounded prefix seek)

Escaping Literal % and _ Characters in SQL Queries

When searching for financial discounts, percentages, or database identifiers with underscores, wildcards must be escaped:

  • The Problem: WHERE discount LIKE '%50%%' fails because the database treats the middle percent sign as a wildcard instead of a literal percentage!
  • The Solution: Use the ESCAPE clause to designate an escape character: WHERE discount LIKE '%50!%%' ESCAPE '!';.
  • Underscore File Search: To find file names like invoice_2026.pdf: WHERE filename LIKE '%invoice!_%.pdf' ESCAPE '!';.

Chapter Summary

SQL wildcards (% and _) provide dynamic pattern matching capabilities in text filters, allowing engineers to query substrings, prefixes, and fixed-position characters across database records.

  • Percent Wildcard (%): % matches zero, one, or multiple arbitrary characters anywhere in the string.
  • Underscore Wildcard (_): _ matches strictly one character at that exact positional slot.
  • B-Tree SARGability: Prefix patterns (LIKE 'Prefix%') leverage B-Tree indexes; leading wildcards (LIKE '%Suffix') force full table scans.
  • Literal Escaping: Use the ESCAPE keyword (e.g. ESCAPE '!') when searching for literal '%' or '_' characters.
  • Case Sensitivity: Standard LIKE is case-sensitive in PostgreSQL and case-insensitive in MySQL; use ILIKE or UPPER() for case-insensitive matching.
