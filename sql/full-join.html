FULL OUTER JOIN

15 Min Read • Module 1: Basics

The Corporate Merger Employee Reconciliation Analogy

Imagine Company A acquiring Company B, and HR combining both separate payroll databases into a single master audit:

  • 1. Employees in Both Companies:: Engineers who worked jointly on shared projects appear paired together across the row.
  • 2. Company A Exclusives:: Legacy Company A staff have no records in Company B; they appear with Company B attributes filled with NULL.
  • 3. Company B Exclusives:: New Company B staff have no records in Company A; they appear with Company A attributes filled with NULL.
  • 4. Complete Visibility:: Zero employees are discarded from either company; every human being from both sides is represented.

FULL OUTER JOIN merges the complete contents of both tables, retaining all records regardless of whether a matching relationship exists.

Syntax & Statement Grammar

The standard SQL syntax and pattern rules for FULL OUTER JOIN:

Query 1: Multi-Table Relational Join 
SELECT 
    a.client_name AS domestic_client,
    b.client_name AS international_client,
    COALESCE(a.account_id, b.account_id) AS master_account_id
FROM domestic_accounts a
FULL OUTER JOIN international_accounts b ON a.account_id = b.account_id;

Query 2: Multi-Table Relational Join 
SELECT 
    a.account_id AS unique_to_domestic,
    b.account_id AS unique_to_intl
FROM domestic_accounts a
FULL OUTER JOIN international_accounts b ON a.account_id = b.account_id
WHERE a.account_id IS NULL OR b.account_id IS NULL;

Query 3: Multi-Table Relational Join 
SELECT 
    COALESCE(e.department_name, d.department_name) AS department,
    COUNT(e.employee_id) AS staff_count
FROM employees e
FULL OUTER JOIN departments d ON e.department_id = d.department_id
GROUP BY COALESCE(e.department_name, d.department_name);

Core Concepts & Engine Mechanics

The FULL OUTER JOIN (or FULL JOIN) combines the results of both LEFT JOIN and RIGHT JOIN. It returns all rows from both tables, matching rows where possible and placing NULL values in attributes where no counterpart exists.

  • Symmetric Complete Union: Every row from Table A and every row from Table B appears in the output. Non-matching attributes on either side become NULL.
  • The Reconciliation Standard: FULL OUTER JOIN is the premier tool in data warehousing for financial auditing, data reconciliation, and gap analysis between staging and production systems.
  • MySQL Workaround: MySQL does not natively support FULL OUTER JOIN syntax; developers simulate it by taking the UNION of a LEFT JOIN and a RIGHT JOIN.
  • Pairing with COALESCE: Always use COALESCE(a.id, b.id) to extract a consolidated, non-null identifier from the combined result.

Detailed Technical Breakdown & Syntax Comparison

Join Condition State Left Table Output Right Table Output Resulting Tuple Use Case
Match in both A and B Populated values Populated values Combined non-null row Shared records
Row in A only (No B) Populated values NULL values Left populated, right NULL Entities unique to A
Row in B only (No A) NULL values Populated values Left NULL, right populated Entities unique to B
Bidirectional Gap Check WHERE a.id IS NULL OR b.id IS NULL Isolates all non-matches Discrepancy reconciliation

How to Emulate FULL OUTER JOIN in MySQL

Because MySQL is one of the few major relational engines that lacks native FULL OUTER JOIN syntax, developers use set unions:

  • The Architecture: Combine a LEFT JOIN (all A + matched B) and a RIGHT JOIN (all B + matched A) using UNION.
  • The Deduplication: Because standard UNION automatically deduplicates identical rows, the intersecting matches are preserved exactly once.
  • Example: SELECT * FROM A LEFT JOIN B ON A.id = B.id UNION SELECT * FROM A RIGHT JOIN B ON A.id = B.id;.

Real-World Practical Scenario

Enterprise Banking Ledger Reconciliation Audit: Compare internal core banking accounting transactions against external Federal Reserve clearinghouse settlement records.

Sample Schema Reference • Visual Dataset 
/* ========================================================
   Sample Dataset:
   internal_ledger: (txn_id, amount, status)
   #T1: $500, POSTED | #T2: $1200, POSTED | #T3: $350, POSTED
   fedwire_settlement: (wire_id, txn_id, settled_amount)
   #W1: Txn T1, $500 | #W2: Txn T2, $1200 | #W3: Txn T99, $8000
   Note: Txn T3 is in internal ledger only. Wire W3 (Txn T99) is in Fedwire only.
   ======================================================== */
Production Query 1: Multi-Table Relational Join 
SELECT 
    COALESCE(i.txn_id, f.txn_id) AS reconciled_txn_id,
    i.amount AS internal_amount,
    f.settled_amount AS clearinghouse_amount,
    CASE 
        WHEN i.txn_id IS NOT NULL AND f.txn_id IS NOT NULL THEN 'MATCHED'
        WHEN i.txn_id IS NOT NULL AND f.txn_id IS NULL THEN 'MISSING_IN_CLEARINGHOUSE'
        ELSE 'UNRECOGNIZED_INCOMING_WIRE'
    END AS reconciliation_status
FROM internal_ledger i
FULL OUTER JOIN fedwire_settlement f ON i.txn_id = f.txn_id;
How this query works: Performs a relational join on internal_ledger to combine matching rows across primary and foreign keys. Click Try in Editor to run and inspect the combined result set.
Production Query 2: Multi-Table Relational Join 
SELECT 
    i.txn_id AS unposted_internal_txn,
    f.txn_id AS unrecorded_clearinghouse_txn
FROM internal_ledger i
FULL OUTER JOIN fedwire_settlement f ON i.txn_id = f.txn_id
WHERE i.txn_id IS NULL OR f.txn_id IS NULL;
How this query works: Performs a relational join on internal_ledger to combine matching rows across primary and foreign keys. Click Try in Editor to run and inspect the combined result set.
Production Query 3: Multi-Table Relational Join 
SELECT 
    COALESCE(SUM(i.amount), 0) AS total_internal_booked,
    COALESCE(SUM(f.settled_amount), 0) AS total_clearinghouse_settled,
    COALESCE(SUM(i.amount), 0) - COALESCE(SUM(f.settled_amount), 0) AS net_reconciliation_variance
FROM internal_ledger i
FULL OUTER JOIN fedwire_settlement f ON i.txn_id = f.txn_id;

Chapter Summary

FULL OUTER JOIN merges the complete contents of both tables, retaining all records regardless of whether a matching relationship exists, making it the premier tool for database synchronization and reconciliation audits.

  • Bidirectional Retention: Preserves 100% of rows from both the left and right tables; non-matching attributes are filled with NULL.
  • The Reconciliation Standard: Ideal for financial audits, data warehouse discrepancy checks, and gap analysis.
  • Always Use COALESCE: Wrap primary keys with COALESCE(a.id, b.id) to maintain a valid identifier across all output rows.
  • Bidirectional Anti-Join: Filter with WHERE a.id IS NULL OR b.id IS NULL to isolate discrepancies unique to either table.
  • MySQL Workaround: Simulate FULL OUTER JOIN in MySQL by taking the UNION of a LEFT JOIN and a RIGHT JOIN.
