SQL Operators Reference

15 Min Read • Module 3: References

The Swiss Army Toolkit Operator Analogy

Picture a master engineer carrying a versatile multi-compartment Swiss Army toolkit into a maintenance hangar:

  • 1. Compartment 1: Arithmetic Tools:: Calipers, rulers, and scales perform mathematical computations: Addition (+), Subtraction (-), Multiplication (*), Division (/), Modulo (%).
  • 2. Compartment 2: Comparison Gauges:: Thickness gauges verify whether a steel bolt fits the tolerance: Equal (=), Not Equal (<>), Greater Than (>).
  • 3. Compartment 3: Logical Interlocks:: Safety circuits determine if both emergency switches are on: AND, OR, NOT.
  • 4. The Universal Mechanics:: Every SQL query ever written is constructed by combining these fundamental tools to manipulate data.

SQL operators provide the fundamental computational instruments for arithmetic calculations, equality comparisons, and boolean logic.

Beginner Tutorials: Practice using these operators in step-by-step tutorials: The WHERE Clause, The AND Operator, The OR Operator, and The NOT Operator in Module 1.

Syntax & Statement Grammar

The standard SQL syntax and pattern rules for SQL Operators Reference:

SQL Syntax Grammar • operators.sql 
-- 1. Arithmetic Operators (+, -, *, /, %)
SELECT 
    item_id,
    unit_price,
    quantity,
    (unit_price * quantity) AS subtotal,
    (unit_price * quantity * 0.08) AS tax_amount,
    quantity % 12 AS remaining_loose_items -- Modulo: remainder after division by 12
FROM order_lines;

-- 2. Comparison Operators (=, !=, <>, <, >, <=, >=)
SELECT employee_id, salary
FROM employees
WHERE salary >= 75000 AND department_id <> 10;

-- 3. String Concatenation Operator (|| in ANSI / + in SQL Server)
SELECT 
    first_name || ' ' || last_name AS full_name
FROM staff_directory;

-- 4. Compound Bitwise Operators (Supported in PostgreSQL / SQL Server)
SELECT 
    permission_mask,
    permission_mask & 4 AS read_permission_flag -- Bitwise AND
FROM role_permissions;

Core Concepts & Engine Mechanics

SQL operators are reserved words or characters used in SQL statements to perform mathematical calculations, string manipulations, comparison tests, and logical evaluations across table attributes.

  • Four Primary Categories: SQL operators divide into: Arithmetic (+, -, *, /, %), Comparison (=, <>, <, >, <=, >=), Logical (AND, OR, NOT, IN, BETWEEN, LIKE), and Bitwise (&, |, ^).
  • Operator Precedence: Operators are evaluated based on strict hierarchy: Multiplication/Division/Modulo execute before Addition/Subtraction; Comparison operators execute before Logical operators; AND binds tighter than OR.
  • Modulo Arithmetic (%): The modulo operator (%) returns the integer remainder of a division (e.g. 10 % 3 = 1), ideal for round-robin sharding and even/odd filtering.
  • Parentheses Dominance: Always use explicit parentheses to override operator precedence and guarantee predictable mathematical and logical evaluations.

SQL Operator Precedence Hierarchy Table

When a query contains multiple operators, the database evaluates them in strict order of mathematical precedence:

  • Level 1 (Highest): Parentheses () and Unary signs (+, -).
  • Level 2 (Multiplicative): Multiplication *, Division /, Modulo %.
  • Level 3 (Additive): Addition +, Subtraction -, String concatenation ||.
  • Level 4 (Comparison): =, !=, <>, <, >, <=, >=, LIKE, IN, BETWEEN, IS NULL.
  • Level 5 (Logical NOT): NOT boolean inversion.
  • Level 6 (Logical AND): AND conjunction.
  • Level 7 (Lowest): OR disjunction.

Real-World Practical Scenario

Enterprise E-Commerce Warehouse Palletization & Invoice Calculation: Calculate shipment shipping weights, pallet boxing remainders, and discounted order invoices using the full suite of SQL operators.

Production Queries • Enterprise E-Commerce Warehouse Palletization & Invoice Calculation 
/* ========================================================
   Sample Dataset: order_invoices
   order_id | item_qty | unit_price | discount_rate | shipping_rate
   ---------+----------+------------+---------------+--------------
   101      | 25       | 10.00      | 0.10          | 15.00
   102      | 48       | 25.00      | 0.15          | 25.00
   103      | 7        | 50.00      | 0.00          | 10.00
   ======================================================== */

-- Requirement 1: Complete financial calculation using arithmetic operators (+, -, *)
SELECT 
    order_id,
    (item_qty * unit_price) AS gross_subtotal,
    (item_qty * unit_price * discount_rate) AS discount_savings,
    ((item_qty * unit_price) - (item_qty * unit_price * discount_rate) + shipping_rate) AS final_invoice_total
FROM order_invoices;
-- Matches Order 101: Gross: $250, Savings: $25, Shipping: $15, Final Invoice: $240.00

-- Requirement 2: Warehouse packaging logistics using integer division and modulo (%)
-- Pallets hold exactly 12 items per case:
SELECT 
    order_id,
    item_qty,
    item_qty / 12 AS full_cases_packed,
    item_qty % 12 AS loose_items_remaining
FROM order_invoices;
-- Matches Order 101 (25 items): 2 full cases, 1 loose item remaining
-- Matches Order 102 (48 items): 4 full cases, 0 loose items remaining

-- Requirement 3: Multi-operator comparison and logical evaluation
SELECT order_id, item_qty, unit_price
FROM order_invoices
WHERE (item_qty > 20 AND unit_price >= 10.00) OR discount_rate = 0.00;
-- Matches: Order 101, 102, 103 (All qualify through compound boolean conditions)

-- Requirement 4: Verify modulo operator in even/odd order routing
SELECT order_id, 
    CASE WHEN order_id % 2 = 0 THEN 'PACKING_LINE_A' ELSE 'PACKING_LINE_B' END AS warehouse_lane
FROM order_invoices;
-- Matches: Order 101 & 103 on Lane B, Order 102 on Lane A

Chapter Summary

SQL operators provide the fundamental computational tools for arithmetic calculations, equality comparisons, and boolean logic, powering every data transformation in relational databases.

  • Four Primary Families: Master Arithmetic (+, -, *, /, %), Comparison (=, <>, <, >), Logical (AND, OR, NOT), and String (||) operators.
  • Modulo Operator: Use modulo (%) to obtain the remainder of integer division, ideal for packaging and sharding logic.
  • Strict Operator Precedence: Remember that * and / precede + and -; AND precedes OR. Use parentheses to enforce explicit evaluation order.
  • String Concatenation: Use || in ANSI standard, PostgreSQL, and SQLite; use + in SQL Server to concatenate strings.
  • Safe Division: Always safeguard division operations against divide-by-zero errors using NULLIF.
